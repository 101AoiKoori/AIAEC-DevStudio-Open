# 项目历史归档

按项目内实际发生的研发与实验复原数据集、脚本、模型和必要技术配置。技术文件归 `Archive/technical/`，文档版本查 Git。查询按只读执行，整理按目录与文档约定处理，涉及素材时核对实验来源。归档作为对应版本的技术证据。

## 证据和迭代

- 先明确项目、时间、分支和资料范围，检查 Git 状态与历史、当前资料及用户指定来源。按文档治理 Skill 直接记述来源、原路径、版本或时间、取得方式和实际状态；缺失写缺失，中途停止写中途停止。区分原始证据、逐字复原、引用及基于证据的解释。
- Git 提交是可定位的版本，不自动等于一次技术迭代。按任务或技术主题梳理有证据支持的基线、变化、结果和后续状态；逐项给出前后提交、原文路径或实验记录，说明比较口径及未经验证之处。无法判断边界时标为待确认，不编造迭代次数或结论。
- `Archive/technical/revisions/<任务>/<技术对象及版本号>/` 按任务和版本组织历史技术文件，尽量减少目录层级并保留可理解的对象名称与版本号。目录沿用已有或用户明确采用的技术对象标识；正式版本及版本目录的创建遵循 [AGENTS](../../../AGENTS.md#数据设计与实现) 的发布授权。通过已有索引记录原工作空间路径、确切 Git 提交或其他来源、版本边界和相邻变化。目录名不用 Git 哈希或其他不透明编码，不覆盖已有版本；不要将文件版本序号误称为项目迭代次数。
- 记录确切提交或其他来源、原路径、所选文件范围和未包含的资料。技术快照不手改；重新复原时不得覆盖不明或用户修改过的资料。禁止纳入文档或包含文档内容的配置。Git 为已追踪版本的权威来源。无法在本工作空间直接取得的工作空间历史，可从可访问且经核实的其他位置复原；需证明对应的是本工作空间内发生的版本，记录来源及缺失，绝不执行工作空间外的脚本。
- 本工作空间实际使用的外部数据或模型可记录为国赛实验的输入或对照，保留来源和适用限制。禁止将相邻工程独立产生的历史数据集、模型及其版本归入本工作空间的归档；相邻工程的训练、数据版本及结果不构成国赛迭代。归属不明时标记待核实，暂不归档。
- `Archive/technical/iterations/` 放有明确主题的对照记录，引用提交及原文件；允许同一提交涉及多个主题。每条变化须能回到具体证据，避免把旧决策或指标描述成当前事实。新增迭代结论前先检查已有任务记录，保留适用范围与时间。

## 素材与边界

- `Archive/technical/materials/` 提供按任务、类型组织的统一入口与来源清单；记录原位置、用途、真实性、许可及当前存在状态。不要读取、复制或记录凭据。区分原件、派生数据、模型和试验输出，避免将合成同源数据写成独立实拍证据。
- 按[统一工程与快照位置](../../../datasets/README.md#单文件编辑与生产接线)归档已替代版本、退役版本或需保留的复现基线。登记原路径、父来源和派生关系，原批次 manifest 保留生成时证据。大型忽略文件按本机实际存在状态和可恢复位置记录。预览、工作副本与自动备份按证据分类，未知归属留在原位待核，临时测试夹具放 `tmp/`。
- Registry 是分类目录快照，不监控文件系统。归档前按任务范围盘点现存 `.blend` 和 `.blend1`，与 registry 记录核对并注明覆盖范围；只凭 registry 行不能认定源文件当前存在。旧 manifest 的 `source_blend`、`scene_file` 等只保留生成时路径声明，除非另有明确关系证据，不将其提升为已核实的模型谱系。
- 分类时区分共享母场景候选、任务工作副本、任务模型源、实验分支、自动备份/疑似孤儿待核和有证据的停用版本。停用或清理前核对活动路径、清单关系及是否保留唯一可复现状态；逐字节相同不代表工作路径可删除，`.blend1` 与现文件不同也不证明它有独立迭代价值。
- 将原始素材统一归类；先核对来源、空间、引用和已有工具，迁移原件时保留来源映射、修复引用并验证，不覆盖数据。大型数据、原始素材、模型和本地输出遵守 Git 忽略及部署边界。未被 Git 追踪的数据不能从 Git 推定其历史内容。
- 归位的小样保留原清单字节，原清单中的当前小样路径按该历史批次的原根目录映射到归档位置，不能把全局当前小样入口改指历史批次。Blender 快照按原字节保留，在独立后台进程重开并检查迁移前后外部资源的可解析性；保持交互式工程状态。移动记录与登记库路径别名相互对应，文件归档不补造未核实的来源关系。临时重建位置不能作为唯一保存位置。外部资料须核对来源和使用许可，缺失时标记待核实；不引入正式运行依赖，不对外分发。

研究说明按现有文档入口维护，当前方法与分析见 `docs/research/`，被替代的研究记录按根目录约定归 `refs/archive/`，文档版本查 Git。实验图签、模型和可复现场景按各自数据与技术归档位置保存，不能仅因目录名为 `research` 就当作文档处理。临时研究图和测试夹具可留 `tmp/`；被选作长期比较基线或唯一复验证据时，沿实际引用核对是否需要归位。只读检查发现此类问题时提供证据及建议位置，保留用户正在运行的输入与输出。

## 校验和交付

核对快照来源提交、原路径与内容，确认比较两侧和引用可访问；报告范围、遗漏、无法复原的内容及原因。更新目录入口和受影响的当前规范，检查 Git 变更，按工作空间约定提交可提交的阶段成果。归档快照应清晰标识为历史证据，不能污染当前文档检索或冒充实车、训练验收。
