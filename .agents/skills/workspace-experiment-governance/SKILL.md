# 视觉训练与实验

训练、微调、评估或比较视觉模型时使用。跨阶段研发从 [vision-model-workflow](../vision-model-workflow/SKILL.md) 接续；素材选择、组合及数据生成按 [dataset-production-loop](../dataset-production-loop/SKILL.md) 执行。只做用户请求范围内的实验；只读比较不自动重训、修改数据或新增报告。

## 从目标到训练

按任务读取 `config/task_targets.yaml` 的学习目标、`config/combination_axes.yaml` 的对照设计，以及对应任务的训练配置和已有结果。八项数据任务各有自己的目标与标签，复用同一训练能力；实拍目标、实拍底图合成与 Blender 按实际素材和任务需要组合。旧脚本及其参数是现状证据，不能自动成为任务需求；发现不合理限制时修正或替换受影响入口。

用已具备完整图签的可行数据推进一次基线，后续依据漏检、误检、类别混淆或任务失败补可控合成；需要真实成像条件时定向补拍，再按用户指定的目标和预算微调。缺少某类实拍、独立新采集、固定来源比例、理想覆盖或人工签收，不构成合成、基线或有限改进的普遍前置条件；人工字段只记录真实人工行为。无法处理的局部说明缺项，其他可行分支继续。训练、续训和具体权重入口见[训练流程](../../../docs/TRAINING_WORKFLOW.md)。

## 来源、数据与结果

- 区分任务标签和范围、采集或生成方式、父来源、用途及 split；同一原图或母场景的派生样本不是新的独立采集。按实际清单记录实拍、增强、图像合成、Blender 渲染及其可交叠的处理步骤，不把设计比例当实测分布。[来源与生成方式](../../../docs/DATASET_DESIGN.md#数据来源与生成方式的定义)
- 确认所用类别、字符或关键点顺序以及标签含义；空负例、漏标、未知和遮挡分别表达。保留并复用已有机器观测，人工确认只记真实行为；标注状态与人工记录维护见[数据权威记录](../workspace-doc-governance/references/data-authorities.md#annotation-state-layers)。
- 训练、验证、测试的分配及历史接触如实记录；同源复用可用于相应诊断，但不表述成独立来源验证。测试集不用于选模或调参。比较模型时明确所用样例、分母、排除项、阈值与指标；微调前后优先使用相同口径，说明数据域和来源变化。
- 将实际数据版本或清单、配置、代码版本、环境、训练运行、模型权重、指标和失败样例关联起来，复用已有 manifest、回执、`run_metadata` 与日志。记录实际数量、失败和中断；未测条件保持未知，不能以设计覆盖或训练完成代替效果结论。
- Blender 素材按实际母场景、版本、配置及已核实父关系记录；渲染派生不算新的独立母场景。登记库是分类快照，选择资产时还要确认文件存在，不把历史路径声明推断为已核实二进制身份。[Blender 资产与谱系](../../../datasets/README.md#单文件编辑与生产接线)

## 运行、接续与交付

按本次目标核对入口参数、数据及输出位置、资源预算与停止条件；复用适用于当前输入的检查，避免为形式重复运行。中断或无进展时先查进程、日志、已有输出与检查点，再决定恢复、修复或重试，不重复启动活跃任务。明确记录失败、空 split、OOM、超时或恢复不兼容，不将失败写成成功。

保留用户原件、人工内容、权重、V3 记录、持久回执和比较所需基线；确认错误的小样或相应 split 按已授权的目录规则重生成。文件位置与替换用 [workspace-file-governance](../workspace-file-governance/SKILL.md)；修改共享代码时用 [shared-code-interfaces](../shared-code-interfaces/SKILL.md)。

跨机训练按[训练包构建与启动](../../../docs/TRAINING_WORKFLOW.md#v4-任务包构建与启动)交付任务目录和共享 `portable_env`，记录实际 Python、依赖和硬件；包内不依赖原工作区，解释器及驱动要求按实际环境说明。交付具体 `.pt`、训练配置和运行来源；训练指标不自动代表其他数据域或目标机结果。正式推理、模型装载、部署配置或 ROS 接口改变时，按 [workspace-offline-delivery](../workspace-offline-delivery/SKILL.md) 评估影响，单次研究训练不自动启动部署流程。
