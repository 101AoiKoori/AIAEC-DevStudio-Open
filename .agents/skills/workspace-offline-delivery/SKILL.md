# 离线交付与目标机验收

影响正式运行行为的共享模块、部署模型、依赖或接口变化时自动做轻量交付影响评估：指出受影响环境和需要复核的验收结论。纯注释、格式和仅研究用模型不自动触发；不因文件位于共享目录就宣布全部旧证据失效。只有本次任务涉及交付/部署/联调/验收时展开相应步骤；只准备交付包不自动传输、安装或启动车辆，普通实验不启动完整交付流程。

## 从实际状态确定交付范围

- 读取本次 Git 变更、真实配置和加载入口；沿用 `docs/OFFLINE_DEPLOY.md` 的交接方式，目标接口以 `docs/HARDWARE_INVENTORY.md` 的实测项为准。未知路径、topic、地图、坐标和设备不填默认猜测。
- 检查源码、Python 打包清单、`package.xml`、CMake、部署配置、模型和实际导入依赖。清单可能不完整，延迟导入和可选模型也要按启用功能核对；构建成功不能证明模型可加载。
- 启动命令只能引用实际存在的入口；没有 ROS 节点或 launch 时报告未实现，不编造命令。配置中有字段不代表已接入调度或运动控制。
- 简明列出交付的 Git 提交及未提交差异、包和配置、单独模型、依赖版本、执行入口、已完成检查及未完成项。利用现有记录，不每次新增报告文件。
- 核对入口文档、正式配置与模型记录是否指向同一当前方案，尤其检查默认策略、权重、启动入口及“已验证/未实现”等状态。维护一处详细交付证据，其余入口引用；旧环境或旧模型的结果保留适用版本，不能自动升级为当前验收。文字精简按文档治理准则执行。

## 可移植性与模型兼容

- 目标为 Ubuntu 20.04 / ROS Noetic / Python 3，具体 Python 小版本、CPU 架构、框架及设备驱动必须核实；不能把 Windows 虚拟环境复制成 Ubuntu 环境，也不能无依据升级依赖。
- 模型核对格式、架构、类别/字符表、输入尺寸、预处理及加载器。正式模型位置遵循 `docs/PERCEPTION_DEVELOPMENT.md`；同名多文件模型须解决冲突，不能误覆盖其他模型。明确替换目标、已有授权和来源后可更新，不把缺模型当作可选成功。
- 检查大小写、相对路径、包安装清单及跨机器路径；不依赖 lab、refs、datasets 或外部脚本作为正式运行组件。文件治理与来源许可沿用现有 Skill。
- 传输与安装按本次授权范围操作，不顺带覆盖现场地图、标定和未提交改动。用户已明确授权更新某项现场资料时，核对目标、来源和现有改动后执行，不重复索要同一授权。代码修订历史统一使用 Git，模型与配置来源需明确。

## 验收证据

每个受影响项目记录环境、代码/模型/配置、输入/命令、观测及限制，状态为通过、失败、未运行或受阻。下表是独立证据层级，不是每次必须执行全部：

| 层级 | 能证明与不能推断的内容 |
| --- | --- |
| Windows 离线 | 本机范围的行为；不能证明 Ubuntu、ROS 或实车兼容 |
| Ubuntu 目标机 | 实际 Python 导入、模型加载、首帧及资源行为；不能替代 ROS 接口和车辆测试 |
| ROS 集成 | 构建、真实入口、消息/action/frame 和接口；不能以 prepare_route 通过证明车辆行驶安全 |
| 受控实车 | 现场标定、门控、失败处理及相应路线；单项通过不能代表全路线和比赛完成率 |

- mock、跳过、缺模型、历史结果或仅热缓存结果不得写成当前全面通过。改模型、预处理、接口或关键配置后复核相关旧结论。
- 加载和运行预算引用当前项目方向，包含必要预热、切换和失败；不能靠漏算必要模型得到合格时延。
- 到达相应分支或等待线等决策点时，未取得可靠且新鲜的门控结果不得放行；其他运动仍须符合已确认路线、现场标定、安全条件及本次授权。车辆运动及替换运行中控制链按本次实际授权处理；不要为通过验收开启全部任务、绕过门控或无限重试。

## 交付状态随变更同步

交付涉及已有需求事项时关联其 ID；仅更新本次受影响的实现与验收状态，普通打包维护不强建识别事项。模型引擎替换需核对引擎身份、原始结果、分数含义与门槛、依赖和下游记录，不能沿用旧引擎名称或分数阈值；接口结构相同也须重验这些语义。异步接口变更检查运行身份、超时/取消、资源所有者和原始文件引用的生命周期。

设计阶段允许使用明确的接口假设继续开发，实际运行参数在部署阶段核实。没有目标机不会阻塞文档、核心实现或交付准备；相应目标机验收保持未运行。交付清单直接使用当前有效文档，过期方案归档并修复入口，勿把旧方案一并交给执行者选择。

## 受阻与交接

明确报告未完成项、实际原因、已取得证据、对交付的影响以及继续所需的信息或操作。缺目标机时可完成交付包准备，目标机验证标为未运行。用文档 Skill 按需更新已有交付/接口记录，合并共同证据和阶段提交。
