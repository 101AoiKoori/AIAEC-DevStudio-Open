# 数据与配置操作

从用户指定的任务和对象开始。用稳定 ID、任务配置键或当前文件定位记录，先读取现值和直接消费者。只读请求直接返回记录和出处。修改时用该对象已有的写入口，读回实际结果，再同步受影响的当前数据和引用。用户只要求同步时，沿用当前定义。

| 对象 | 操作入口 |
| --- | --- |
| 识别需求、监督目标、组合轴、任务配置 | 在唯一维护源改对应任务或键。识别需求、设计和生成检查见[文档维护源](../workspace-doc-governance/SKILL.md#源文件与生成物)。任务输入、用途与分集声明按[数据记录对应表](../workspace-doc-governance/references/data-authorities.md)定位。 |
| 当前逐图记录和机器证据 | 按[逐图库入口](../../../datasets/scripts/README.md#逐图入库与资格查询)使用 `query_frames`、入库和分配。查询按 `frame_id` 或 `record_id` 缩小范围。补证使用原图和实现要求的证据，读回受影响的任务、用途和 split。旧决策用旧 `record_id` 追溯。 |
| 小样、导出与训练输入 | 从当前图签和真实批次清单核对下游配置与路径。需要生成、打包或原位替换时，使用 [dataset-production-loop](../dataset-production-loop/SKILL.md) 与 [workspace-file-governance](../workspace-file-governance/SKILL.md)。路径过时先核对原训练意图和现存数据，再改入口。 |

校对计划登记时，先对照任务 `source.yaml` 的入口、`config/task_targets.yaml#tasks.<task>.plans` 的唯一全局计划登记，以及当前 manifest 实际引用的生成输入。已执行批次的输入快照与当前可写配方分别记录；确认逐状态及实际图签对应后，将当前配方归回已有任务配置入口，manifest 的 `plan` 指向该入口，`generation_plan` 保留生成时输入。预算和缺额从计划读取，选源摘要通过引用计划表达，避免另存一组动态计数。

当前小样的实际数量由既有 manifest 维护；仅有实际样本清单时通过任务 `source.yaml#sample_manifest` 定位，不倒造一份配额计划。历史配方可保留在已有 `legacy_*_plan` 引用下，同时移出当前计划列表及相应 `plan_usage`，检查旧调用方并同步生成统计。提取器未识别现行计划结构时，按真实清单核数并说明生成统计的未知范围，不能把未识别解释成零覆盖或新增停止条件。历史回执保留当时声明，不能因旧计划仍存在就计为本轮未完成批次。

定向微调计划在既有 `plans` 登记并用 `plan_usage: fine_tune` 单列，不抵扣基础全量计划配额。任务来源配置指向专项计划与实际清单，训练配置消费专项数据入口；基础集合及其已执行运行保留原输入记录。生成时配方保留在清单快照，逐图解析后的类别与数量供当前计划统计读取。

便携包新增数据目录时，训练引擎只读取该数据入口相邻的证据映射，不会自动继承基础数据目录的 `source_records/evidence_map.json`。复用基础图签须将继承的证据键解析到包内已有文件，新增图签引用其实际来源和几何核对证据；保留原键与内容哈希供追溯。交接前调用实际包内 `preflight_dataset` 核对证据接线，描述性图签 audit 不代替训练消费者预检。

任务切换到全量集合时，在任务 `dataset.yaml#actual_manifest` 指向当前集合汇总清单；`sample_output` 继续保留小样入口。实际统计优先读取显式 `actual_manifest`，未设置时沿用小样清单，不从全量计划预算推断已产量。

火焰与禁行牌的现行计划和实际图签对账使用已有入口 `python -B lab/scripts/contracts/state_coverage.py --actual --json`，需要逐图库存时加 `--source-status`。查询读取当前清单、配对标签及实际楼宇或几何记录，图片数、实例数和分集分别报告。计划请求数量不能替代实际标签数，背景保留的原有正例不能计为空负；其视面未记录时保持未知。清单正在变化或图签缺失时报告读取范围，其他统计仍按实际可读内容处理。

## 变更时同步相关入口

局部替换当前图签时，先暂存并核对新图签，保留退出记录和未替换文件的哈希，再同步当前清单及其消费的完整配额计划；原 `generation_plan` 保留原批次输入，增量回执单独追溯。当前计划按替换后的实际状态核数，不能继续用基础批次的分支配额解释当前产物。空负标签保持同名空文件，不通过删除正例标签制造负例；失效掩膜、预览和训练缓存随对应生成图处理。

制作 Agent 切换计划或 split、改变清单路径或字段含义时，在本轮调用本 Skill；不等下一次对账发现旧引用。沿实际依赖处理：任务 `source.yaml` 的执行入口 → `task_targets.yaml` 的计划登记 → 统计提取器与消费入口 → 现有生成文档。`combination_axes.yaml` 只维护组合设计，不复制计划列表。历史计划保留生成时输入，当前计划登记不计入历史批次。只读请求只报告差异。

先用实际字段解释未知：火焰 `target.count` 与 `target.building` 分开读取，明确的零计数不因楼宇为空而丢失；缺计数仍未知。分集小样切换后按各 split 的现行计划核对状态 ID、实际图签及类别，不能用旧总数直接抵扣新计划。

把变更影响传到对应现有 Skill：制作／重跑改 `dataset-production-loop` 的调用或交接，统计字段／接口改 `shared-code-interfaces` 及实际入口，派生说明改 `workspace-doc-governance`，文件迁移按 `workspace-file-governance`。仅在调用方式、维护源或复用步骤已改变时原位更新 Skill，不往 Skill 写每批动态数量。接手 Agent 读取这些入口；已有并行协作者按现有通信约定交接修改路径、变化字段、受影响消费者和复查命令。Skill 文件本身没有监听进程，通知由正在执行变更的 Agent 完成，不声称无人执行的自动更新。运行中批次不改输入，记录本次未同步范围并继续独立工作。

区分取消一项用途、替换可重建的图签、移动或删除原件。遇到已有入口表达不了的撤销，定位具体记录和消费影响，按当前授权推进其他部分。保留原始证据和历史回执的当时声明。文件落点、清理和正式版本遵循[项目约定](../../../AGENTS.md#数据设计与实现)及文件治理 Skill。

收尾时对照实际消费者执行对应检查。派生文档用原生成器同步，修复本次受影响的现行链接。证据以实际读回、图签、清单或回执为准。交付时给出改动的任务/键或记录 ID、相关产物和检查结果；局部失败说明具体条件和影响，继续已授权且独立的工作。

用户要求暂停时停止新增写入和派工，在安全边界停下，记录最后确认的文件或记录、在途操作和下一步。按 [workspace-collaboration](../workspace-collaboration/SKILL.md#暂停恢复与事项状态) 核实协作方实际状态；恢复时先核对当前记录与工作树，再从断点继续。
