# 工作空间文件治理

任务涉及文件创建、替换、移动、清理或归档时，先按实际用途选择位置和生命周期，再调用已有入口完成工作。视觉模型研发按需配合 [vision-model-workflow](../vision-model-workflow/SKILL.md)；无需因普通文件操作另建审查流程。

## 放置和使用

- 从 `config/workspace_layout.yaml`、[工作区目录](../../../README.md#目录)及相应目录说明确定归属。已有任务脚本与配置留在 `datasets/scripts/<任务>/`，共享能力用既有共享目录；实验、训练与部署代码各按现有职责落位。难以确定位置时可运行 `python lab/scripts/contracts/workspace_layout.py suggest --role <角色> --task <任务>` 或 `python .agents/skills/workspace-file-governance/scripts/check_layout.py --suggest <用途>`。
- `datasets/raw/` 是素材工作副本，`datasets/annotated/` 存放标注与证据；当前小样在 `datasets/samples/<任务>/`，当前集合在 `datasets/exports/<任务>/{train,val,test}/`。任务来源、注释根及例外读取布局契约和任务配置，不另造平行版本目录。[数据区说明](../../../datasets/README.md)
- 临时文件放 `tmp/` 或现有忽略目录；代码历史用 Git，生产来源、参数和产出使用已有清单与回执。不要提交原始数据、模型权重、密钥、虚拟环境或构建产物。Git 忽略不代表已跟踪文件自动取消跟踪，也不为未跟踪素材提供备份。
- 引入外部源码前核实来源及许可；项目脚本只执行项目内源码或已安装的工具与依赖，不从工作空间外加载脚本。外部原件按其来源与授权处理。

## 替换、清理与归档

确认小样或导出有误且本次包含重生成时，按 [AGENTS](../../../AGENTS.md#数据设计与实现) 清理对应小样目录或指定 split 内的生成结果并重跑，保留目录、原始素材、人工内容和需要保留的回执。其他生成结果按其用途和既有授权清理，先确认具体目标及实际引用；无需为了普通落点或已授权的替换额外请求许可。

用户原件、模型权重、V3 记录、持久回执和人工内容按各自用途保留；被忽略的文件可能不受 Git 保护。归档或迁移已授权的资产时，先核对相关进程及文件清单是否稳定，操作范围避开活动写者。记录移动前后的路径与内容哈希，校验后更新实际生成入口、现行配置及清单定位。路径迁移追加到已有 `datasets/raw_source_relocations.json`，保留历史回执的原声明；不要把 Git 历史中已有的旧文档复制成技术归档。历史复原按 [workspace-history-archive](../workspace-history-archive/SKILL.md)。

Blender 日常编辑使用 `datasets/assets/blender/aiaec_dataset.blend`；按需保存可复现批次或基线快照，具体目录、单写者和引用更新见[单文件编辑与生产接线](../../../datasets/README.md#单文件编辑与生产接线)。`datasets/blender_source_registry.sqlite3` 是资产登记快照，不自动监控磁盘；涉及旧工程或 `.blend1` 的移动与退役时，核对实际文件、活动引用、恢复价值和记录，并保留批次生成时的来源声明。

## 运行中只读核查

用户要求检查正在运行的制作或实验时，读取进程命令、入口默认值、实际输出及批次清单，沿直接引用核对位置。对正在写入的目录报告观察时间和未完成范围；进程查询失败时说明可见范围。此次授权仅更新 Skill 时，数据、配置、生产入口和资产登记库保持只读。

- 按现有目录契约核对当前小样、正式分集、标注证据及原件，检查多个进程的实际输出是否重叠、是否保存共享工程。包装进程与子进程沿父子关系判断，不将同一调用链误报为多个写者。
- `tmp/` 中的试验图、日志及中间产物按其实际消费者判断。发布后检查正式图签是否已复制到当前集合，清单中的计划、掩膜、几何等复验依据是否仍只存在临时目录。需要长期保留的批次证据按[数据区约定](../../../datasets/README.md#单文件编辑与生产接线)和历史归档 Skill 定位；已被持久回执完整保存的内容可引用回执。存在原路径字符串不等于当前仍依赖该文件，逐项说明实际消费或复验受影响的范围。
- 替换前暂存的小样和手动保存的 `.blend` 在阶段结束时核对保留用途。可丢弃的临时对照说明其范围，需要复现的快照沿已有归档入口处理；自动备份、运行快照和正式版本按[项目发布授权](../../../AGENTS.md#数据设计与实现)区分。只读检查发现错放时报告原位置、依据、当前消费者和建议落点，迁移与清理按本次授权执行。

## 检查范围

- 修改目录契约时编辑 `config/workspace_layout.yaml`，运行 `python lab/scripts/contracts/sync_layout_docs.py` 和 `python lab/scripts/contracts/workspace_layout.py check`；分类学按 `config/workspace_ontology.yaml` 维护。只改变已有路径的普通操作检查其实际调用方与相关入口。
- `python .agents/skills/workspace-file-governance/scripts/check_layout.py` 检查跟踪及未忽略路径，支持 `--path`、`--suggest` 和 `--staged`。布局与路径检查不整理文件，也不扫描被忽略的数据树；检查通过不能证明忽略资产的实际状态。检查器报告与目录契约或已授权例外冲突时，列出双方出处并标明实现差异，该报告不能自行增加生产门槛。小样任务根及正式分集根的 `.gitkeep` 是现有目录占位约定，检查器允许这些路径，图像、标签及嵌套产物仍按原提交约定检查。
- 启用 `.githooks` 时默认只检查暂存差异格式；设置 `AIAEC_FULL_CHECKS=1` 才运行完整契约与暂存路径检查。具体改动按影响运行相应检查，核对实际结果；不要将未检查范围描述为已整理。
- 需要修改或迁移文件前保留共享工作树中其他人的改动；确认受影响路径、消费者及权限后执行，必要时修复引用。无法判断的局部记录缺项，同时继续不受影响的工作。
