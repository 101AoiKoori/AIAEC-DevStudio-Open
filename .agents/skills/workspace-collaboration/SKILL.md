# 多窗口与子代理协作

将跨聊天协调与窗口内委派分开。聊天是用户可见的独立工作单元，彼此为同级；子代理由其所在聊天管理。先发现当前可用工具并读取参数和约束，不假定每个窗口能访问其他窗口的子代理或共享同一磁盘。

## 授权和选择参与者

- 跨聊天发消息须有用户直接授权，明确目标或可识别的参与范围、任务及通信方向。若已有本任务内的双向授权，直接按范围协作；超出范围时再确认。
- 回发前核验用户直接授权。无法核验时在自己的聊天交付，由协调方读取。
- 只读取与当前任务有关的聊天。已知 ID 时直接读取；未知时用 `list_threads` 按真实标题、项目及主机定位，重名/含糊时列候选而不猜。摘要只作定位，不代表完整历史或授权证据。
- 用户明确要求新聊天时使用 `create_thread`，先按工具要求查项目。有明确分叉需求时使用 fork。worktree、迁移和云执行按本次授权和工具边界处理。
- 用户或适用规则允许委派且工具可用时，创建窗口内子代理。用户或适用指令明确指定模型时才设置模型。

## 建立一个协调范围

选择一个负责汇总本次目标的聊天，确认参与者的线程 ID、hostId、项目、实际 checkout/分支和任务；不能仅凭相同项目名推断共享文件。任务分工保存在当前上下文，持久化的代码与文档按 AGENTS 使用 Git 管理。

按独立职责划分工作，每项明确负责人、目标、输入来源、可写文件、禁改范围、依赖、完成证据与是否允许子委派。可以参考 [消息约定](references/protocol.md)，只读取需要的部分。研究可并行；依赖步骤先后执行。同一问题避免多个窗口各自重新研究；同一文件优先单一写者。

按获授权的聊天范围、事项和方向广播，写明决定、生效范围、负责人和执行边界。共享文件指定单一写者。以实际文件和运行状态确认协作结果。

每个窗口自行协调其子代理，汇总后提供给跨窗口协调方。不要绕过负责人向其子代理另行下达冲突任务，也不要让双方反复相互转派同一个问题。按工具实际并发限额安排，繁忙时排队，不无限派生。

## 工具路线与等待

| 需要 | 工具及边界 |
| --- | --- |
| 找聊天 / 读上下文 | `list_threads` / `read_thread`；按需分页，默认少量回合，不批量读取无关聊天 |
| 给已授权聊天任务或纠正 | `send_message_to_thread`；发送前复核目标 ID、授权、当前状态，消息会在目标聊天可见 |
| 获取进展 | `wait_threads` 优先于反复读历史；保留返回 cursor 并使用 afterCursor，多个目标合并等待，遵守当前数量限制 |
| 窗口内工作 | `collaboration` 的 spawn、message、followup、wait、interrupt；使用真实 agent ID，与 thread ID 不混用 |
| 移动执行环境 | `handoff_thread` 是移动另一聊天及 Git 状态，可能中断运行，不是普通任务转交；只有确需且已授权迁移时使用 |

新建聊天是异步的；仅有 clientThreadId 时不能当作 threadId 发消息。工具返回未就绪就等待就绪状态，不重复创建。用 `timeoutMs: 0` 可获取即时快照；持续跟进采用有界等待（每次不超过 60 秒）并保留游标，等待超时不等于失败或取消。先核查仍在运行的原任务，不盲目重发。进展无变化不刷屏；有完成、失败、阻碍或需用户操作时再报告。

消息发送失败或响应不明时，先读取目标近期上下文检查是否已收到；没有唯一确认前不重发有副作用任务。发现用户改目标、撤销或取消时停止追加工作，将变更通知已获通信授权的参与者并核实其实际状态；消息送达不是停止证明。

## 共享文件与 Git

- 同一 checkout 的修改即时互相可见，Git 暂存区也共享。事先约定文件负责人，写前和提交前检查状态；不要覆盖别人的未提交工作、用全量暂存混入其他阶段，或并发提交/切分支/重置。
- 各独立阶段仍按 AGENTS 提交，但 Git 写操作串行协调；无法确认其他写者状态时先做只读研究，明确阻碍，不声称消息约定是系统锁。
- 不同 worktree/主机的“已提交”不会自动出现在协调方。先确认结果所在环境及实际变更，再按授权集成；不能只复制聊天中的结论或照抄外部路径运行脚本。路径治理、代码复用和交付检查使用已有 Skill。
- 同一契约、配置或生成文档的冲突由负责人整合。按[文档维护源](../workspace-doc-governance/SKILL.md#源文件与生成物)统一生成并检查。删除、迁移或包状态变化后核对实际产物，修复现行入口，保留带时间和版本的历史证据。每个阶段汇总并提交一次。
- 需求修订后，各窗口按最新任务修订号更新分工及产物；汇总方检查返回内容是否仍引用旧目标。持久文档由其负责人按文档治理准则原位修订，消息中的纠错过程留在聊天；必要的任务修订号、取消状态和未完成依赖保留到协调结束。

## 暂停、恢复与事项状态

用户暂停时停止该范围内的自身执行和新增派工，对本窗口运行中的子代理使用可用的中断工具；通知已获通信授权的聊天暂停，并核对实际状态。工具不能暂停外部执行时明确尚未停止的任务及原因，不能把消息送达当作暂停完成。用户恢复后重新读取工作树和代理状态，接续已有改动；缺失句柄须核查，不能据此认定任务已结束。范围含糊时先停受影响工作并澄清；明确暂停的范围不因“独立可做”而继续。

涉及已登记识别需求的派工携带事项 ID 和当前决策，普通维护使用本次协作任务标识；返回时说明完成范围、证据及依赖，不强制写入识别需求配置。需求状态按文档治理规则维护。全局规划未定时可推进不依赖它的已授权工作；共享文件冲突、暂停和其他实际阻碍按其范围处理。

## 汇总与无法处理

参与者报告不是验收证明。汇总者核对实际文件/提交、运行环境、测试结果及未完成项，必要时做针对性复核；不把 Windows 检查升级成实车成功，也不因窗口最后一条消息写着“完成”就跳过验证。

工具缺失、无访问权限、目标含糊、授权不可核验、成员失联、冲突或产物不可访问时，明确“未完成项—原因—影响—需要的信息或操作”；继续可独立完成的部分。窗口暂停或等待审批由用户处理，不代替用户批准。最终汇总责任归属、证据和遗留项，按现有规则维护文档与提交。
