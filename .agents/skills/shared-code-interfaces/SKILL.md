# 共享代码与接口维护

在编写实现前自动使用。只读代码审查按问题范围检查，不改文件；纯注释/格式修改或只运行既有脚本不要求重新设计接口。任务组合与公共收尾按 AGENTS 的职责分工执行。

## 先找能力，再决定实现

- 从本次需求的行为、输入输出、配置键搜索所属代码及调用方：推理查 `ws/src/aec_vision/src/aec_vision/`，实验查相关 `lab/features/`，仓库工具查 `tools/`，Skill 辅助代码查所属 Skill。只沿实际依赖扩大范围，不让普通维护脚本强行复用推理模块。文档是定位线索，存在文件不代表能力已实现。
- 明确候选函数的语义和限制。优先直接调用，其次小范围扩展或局部适配；确有不同职责、行为或生命周期时新增实现，并简述理由。不要为复用率改变需求。
- 正式推理及训练/正式推理共用的模型构建保留在部署包；训练专用的候选结构、训练循环、参数探索和评估留在实验区，不为单次研究提前塞入部署包。候选被正式采用时检查并迁入合适核心，更新实验调用以避免两套正式实现。ROS、CLI、采集和文件输出适配与推理分离；正式包不能依赖实验目录、数据目录或外部脚本。文件落点使用 `workspace-file-governance`。

## 抽象的边界

- 代码相似、字段同名、出现两次都不足以证明可抽象；确认相同语义、稳定职责及真实调用需求。单任务局部函数不必泛化。
- 不为尚不存在的调用方建立插件系统、注册器或继承层；不要用大量任务分支和布尔开关掩盖不同策略。
- 不强行统一任务置信度、角度/坐标、计数归属、未知状态或恢复策略。已有公共函数足够时只加调用，不重构整个架构。
- 模块边界不清时保留局部实现并说明待确认点；不能因此复制已确认的共享推理核心。
- 用户明确要求统一接口或抽象时，解释语义差异并提供满足目标的最小共同接口选项，保留任务特定结果；不能把避免过度抽象作为无条件拒绝需求的理由。

## 接口影响检查

按变更选择相关维度，不强制给每个函数建立一份接口文档：

| 维度 | 需要核对的消费者与条件 |
| --- | --- |
| 输入 | BGR/RGB、dtype、形状、原图/裁剪坐标、单位、时间来源、可变对象是否被修改 |
| 输出 | 字段、序列化、ok/unknown/error/partial 含义、空结果、异常和回退；不能将失败转成零 |
| 配置与模型 | 默认值是否真被调用链消费，类别/字符顺序、预处理、架构、检查点格式与旧配置兼容 |
| 生命周期 | 模型加载次数、共享资源所有者、并发安全、取消/超时、重复或迟到结果；仅在涉及这些行为时展开 |
| 调用链 | 直接调用、实验入口、ROS 适配、配置驱动分支、测试和描述性文档；新增状态值需追查所有消费者 |

删除、改名或改变字段类型/含义同样需要追查消费者；兼容层只服务明确的旧调用方，并说明迁移条件，不为假想调用无限保留旧接口。注释修正若揭示实际契约矛盾，先核实行为，不当作纯格式变更。

对异步识别、模型替换或资源生命周期变更，再按实际影响检查：请求/结果绑定运行、任务、观察身份；重复结果幂等、迟到结果隔离；图像通过文件引用和坐标关系交接；队列、缓存与模型驻留有界，取消和异常路径释放所属临时资源并保留必要原始数据。全局接口未定时记录最小输入输出假设并实现可独立调用的核心，不凭空建立整套调度框架。

例如 `plate.py:create_cnn` 同时服务训练与推理，应保持一份实现；新 OCR 仲裁状态必须检查投票逻辑如何选分数。具体默认策略以当前源码及配置为准。

## 完成与受阻

- 验证实际改变的行为及关键失败分支；共享契约变化覆盖受影响调用方，不用仅导入成功证明兼容。缺模型或依赖时记录未验证项，不将 mock/跳过等同真实通过。
- 修改共享推理或需求后运行 `python tools/sync_docs.py`，需求仍只编辑 `config/perception_tasks.json`，相关文档用 `workspace-doc-governance`。部署影响交由 `workspace-offline-delivery`。
- 实现、删除或改变接口后，搜索受影响入口及研究文档中的能力和状态描述，按当前代码与验证证据更新。例如函数已实现但未实车验证，应分别表达；旧实验章节中的已知限制需区分是当时版本还是当前行为。具体结果集中在所属文档，其他入口引用，按文档治理准则处理文字。
- 将复用/新增理由、接口和调用方影响、实际验证与限制合入本次任务的共同结果；不另建报告或为本 Skill 单独提交。
- 需求矛盾、调用方不可访问、模型契约不明或行为证据不足时，明确无法完成的部分、原因、影响和所需信息；继续独立可行部分，不猜测兼容性。

## 当前方向与需求维护

识别实现沿 `docs/PROJECT_DIRECTION.md` 的已定主线推进。接口假设应可替换，并保留对应输入检查与失败状态；理想硬件前提只用于设计，实际数据无效时仍按契约返回失败。涉及需求事项时按文档治理规则同步状态；普通工具维护不新增识别需求事项。
