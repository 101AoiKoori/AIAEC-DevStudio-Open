# 视觉模型研发

按用户指定的任务、现有进度和预算，将预想比赛场景中的识别目标推进到本次要求的产物。视觉研发交付模型，实车流程由相应协作方负责。

## 五条减法

- **少一些概念。** 让现有 Skill 承担完整的可交付工作，共用能力读取各任务自己的定义。单个动作直接交给已有工具。
- **少一些真相源。** 一项事实只有一个维护入口。说明链接到需求、设计和实际入口；批次快照保留当时的输入与结果。接续时读取当前配置、进程、日志和回执。
- **少一些中间层。** 现有脚本能直接交付，就直接调用。每一层新增能力须有具体调用方与实际用途。删减时，重复流程归现有 Skill，领域事实归维护源，失效入口从工作树移除。
- **少一些普遍规则。** 将反复发生且确实有代价的问题固化到对应层。覆盖原件之类后果严重的风险就地保护；任务阈值、可行组合和当批配额留在本任务。
- **少一些证明负担。** 有可执行的方法，就先在预定识别范围内推进可行批次及基线；用实际图签和识别结果核对，按失败定向补数据或微调。

## 从目标接续

1. 明确本次任务、阶段、预算与交付。按需读 `config/perception_tasks.json` 的识别范围、`config/task_targets.yaml` 的监督目标和 `config/combination_axes.yaml` 的对照设计；旧实现中的条件按实际用途判断。
2. 数据制作使用 [dataset-production-loop](../dataset-production-loop/SKILL.md)。按[全局、任务与批次边界](../../../docs/VISION_ARCHITECTURE.md#数据制作的全局与局部)找到本任务的素材、计划和执行入口。凭当前图签、回执及剩余需求决定从哪一步继续。
3. 训练、微调和评估使用 [workspace-experiment-governance](../workspace-experiment-governance/SKILL.md)，从[训练流程](../../../docs/TRAINING_WORKFLOW.md)选择任务入口和预算内的运行方式。跨机训练执行同一流程的[任务包交接](../../../docs/TRAINING_WORKFLOW.md#生成便携任务包)，使用已投入训练的共享环境。
4. 本次做到模型时，交付实际 `.pt`、对应任务和运行记录，并说明验证覆盖。小样、导出与训练结果分别用实际产物确认。

计划、来源分集、清单或输出字段发生变化时，由修改者在同轮调用 [dataset-config-operations](../dataset-config-operations/SKILL.md#变更时同步相关入口) 完成关联同步；当前进度从实际清单读取。可复用调用方式变更回写对应现有 Skill，不为批次数量新增规则或文档。

## 断点与冲突

续作先核对进程、最后有效输出和日志，再决定继续、重试还是换用可行分支。遇到拒绝，按[全局执行约定](../../../AGENTS.md#数据设计与实现)找当前权威键、值和作用范围。按当前授权修正该维护源或实际拒绝分支，复跑触发该拒绝的入口。需要新增业务规则时，先交给用户决定。处理受影响分支时继续其余可行工作。涉及文件替换时用 [workspace-file-governance](../workspace-file-governance/SKILL.md)。
