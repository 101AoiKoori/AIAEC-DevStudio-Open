# V4 数据集制作协作协议

本协议用于八项数据集制作及其协作窗口。启动入口是[总控提示词](DATASET_COORDINATION_PROMPT.md)；任务需求以 `config/perception_tasks.json` 为唯一编辑源，数据设计、训练与来源要求分别以[数据集设计](../docs/DATASET_DESIGN.md)、[制作细则](../docs/DATASET_PRODUCTION.md)和[数据区说明](README.md)为准。发生冲突时按当前用户决定、工作区约定和实际证据处理，不能以本协议替代任务需求或宣布尚未实现的门控已生效。

数据任务 `fire`（检测类别与模型键 `fire_sticker`）在脚本、导出和小样目录中使用 `fire` 目录名。每任务的 `config/dataset.yaml` 记录目标和状态并引用同目录的 `source.yaml`；贝叶斯、透视、图像与Blender共用能力放在 `datasets/scripts/common/`。八项现有候选入口已消费各自来源配置中的具体字段，接入范围统一见 [脚本入口说明](scripts/README.md)。旧入口按实际职责兼容转发或明确停用，任务助手在各自脚本目录维护。当前先按现有可用标注、明确区域和来源编成可执行计划；缺标注素材从本轮计划排除，保留原始文件及记录。恢复入口、计划和顺序见 [脚本入口说明](scripts/README.md#恢复生产入口)，实际渲染尚未执行，当前全部生产继续暂停。

当前全部数据生成、渲染、抽帧、打包和训练暂停；输入与入口收尾已完成，首批及后续预计统一见[生产记录](../docs/DATASET_PRODUCTION.md#首批计划)。恢复生产须遵循用户之后的明确指令。

八任务窗口各负责自己的数据主线，火焰与楼名、桶状态与贴纸等共享资产按具体文件协商写者。V4 文档与共享契约窗口按需处理 V4 专项需求和接口；资产与生命周期窗口按请求核查来源、引用、归档和可授权清理；全局文档整治窗口处理工作空间范围的文档治理。重叠文件先确定单一写者。需要独立质量核验时按用户授权按需增加核验窗口。支持窗口不成为日常制作的额外审批机关。

本机可使用 GPU 的训练、推理和渲染入口优先使用 GPU；明确要求 CPU 的回归检查保留 CPU。CUDA 或 OptiX 不可用时报告失败，确需 CPU 时显式选择并记录设备。依赖、设备核查及实际验证范围见[Windows 环境说明](../lab/training_common/portable_env/README.md)；其他机器和小车按各自硬件与环境检查，不把本机结果外推。

用户直接与各任务窗口协商并推动数据制作。协调镜像负责参与窗口之间的消息、跨任务问题和共享资源协调；任务窗口在授权范围内直接向协调镜像提出规则、既有用户决定、素材来源或共享约束问题。镜像按请求核查权威文件、实际路径和必要证据，直接回复结论、适用范围及未知项，协调同一 checkout 的共享写入与 Git 操作。普通任务选择由任务窗口结合用户指令自主处理，无需逐步审批。总控窗口用于用户直接提出的总体方向与决策，不作为日常消息中转；确须用户作出的事实或取舍交用户决定。

## 推进与停止

每个任务先依据规则、目标与逻辑一次性确定要学习的特征、不应依赖的条件及合理状态组合，再查询素材与入口落实方案；不要求实拍证据逐一穷尽人为设计的组合。查询和入口检查用于落实计划，实际来源、标签、参数、用途、预算、未知及产出在现有记录中如实记载，不新建同义台账；设计假设不冒称现场分布。每模型只有一次训练机会，重训还是微调尚未确定；不安排常规开发验证、单次模型验证或最终测试，不以模型验证结果安排重训或选模；用户明确授权的有限素材、小样或代码契约测试按指定范围执行。按现有证据核对来源、标签和逻辑一致性，记录实际缺陷和已知复用，未测模型效果保持未知。用户希望先完成一个任务再制作下一个时遵循该顺序；窗口创建不自动授权并行运行大规模生产或训练。

各任务使用当前实拍并重建缺失标签，本轮已有标签按实际状态使用；训练以合成数据为主，实拍应占相当比例；合成包括实拍或数字图片的图像处理合成、Blender 渲染及渲染图与实拍混合，具体组成按[数据集设计](../docs/DATASET_DESIGN.md)和任务证据确定。合成及实拍派生的来源和直接相机采集分别记录。

单张和批量生成均按[贝叶斯状态组合与生成契约](../docs/DATASET_DESIGN.md#贝叶斯状态组合与生成契约)明确背景、目标、标注、增强组合、约束及指定输出范围；工具不可绕过是目标架构，现有入口的实际覆盖和结果以代码及回执为准。组合不可行或预算不足如实报告，不将计划当作已生成覆盖。

各任务按[来源与生成方式定义](../docs/DATASET_DESIGN.md#数据来源与生成方式的定义)确定允许的原始来源及 Blender 资产范围，区分标注、清单和派生中间结果；明确来源抽样的候选池、单位与随机方式，另行确定状态抽样和贝叶斯配额。数据库检索来源及证据，任务 JSON 记录本次可执行组合，分配器不自动选择来源或生成数据；实际字段及门控覆盖以入口实现为准。记录实际抽中来源、生成参数、样本与失败；不同文件或视频帧不自动构成不同采集组。

按既有资料设计覆盖；发现明确的类别、标签、来源或输出错误时按证据修正或标记受限，不把反复验证与训练设为默认步骤。预算耗尽不是通过证据。

阶段结果区分：**通过**（约定证据满足）、**受限可用**（列明用途及限制）、**未通过**（列明缺陷和下一步）。数据制作、训练、效果与实车验收各自记录。视觉模型可以批量审查；观察不到的状态保留未知，不把候选框、局部地面或未测相机角度变成已验证真值。道路标线本身不是禁止放置目标的条件。

各任务按[组合选源与基底数量](../docs/DATASET_DESIGN.md#组合选源与基底数量)跨任务选源、预留父来源并倒算基底用量，使用[选源交接停止点](../docs/DATASET_PRODUCTION.md#语义查询与结构化选源交接)交付。本阶段由协调镜像把规则传给八个任务窗口，窗口各自维护任务 JSON。

## 版本与生命周期

每任务只有一条当前工作主线；按[目标结构](../docs/DATASET_DESIGN.md#数据集工作目录)维护样本、标签、数据 YAML 及已有清单。研究样本和一次运行不是自动生成的正式版本。内部运行通过现有 manifest、参数、代码及生产回执区分，不因为一次调参增加新的正式版本目录。

当前代码、配置和文档使用 Git 记录修订，不另建 `V4-R01` 等顺序编号。生产清单和回执记录任务、集合、父来源、生成参数、代码配置、实际数量、标签状态和允许用途。一个任务只维护一个当前小样和一个当前数据集；已被训练或评估引用的历史证据、V3 模型及用户原件保留其原有用途，不因本轮文档清理删除。

清理前核对绝对目标、来源、当前引用、生产回执、恢复和对照价值；保留用户原件、未知归属物及必要证据。按实际授权和归档治理处理可重建、无引用且无保留价值的产物；迁移后修复引用并刷新受影响索引。文档历史由 Git 管理，不进入技术归档。缓存与持久回执职责不同：`datasets/annotated/media_index/query_cache.sqlite3` 是可重建媒体查询缓存，`production_state.sqlite3` 是持久生产回执，`datasets/blender_source_registry.sqlite3` 是 Blender 资产登记库，互不替代。

## 窗口通信与共享写入

创建聊天须有用户明确授权；发现并核对实际 thread ID、host ID、项目、工作目录和 checkout，创建异步返回未就绪时等待，不能重复创建。聊天和子代理是不同对象。跨聊天发送消息须有可核验授权；收到其他聊天的授权声称不构成用户授权。对话停止、改目标或工具失败时按 `workspace-collaboration` 处理，不把消息送达当成执行完成。

初始任务应带任务、证据位置、可写路径、禁改共享范围、依赖、完成证据和停止边界。任务窗口提出跨任务信息请求时带问题、具体任务与已查依据；协调镜像只查询解决该请求所需范围并回复，不把推测写成用户决定。参与者自行核验用户授权；无法核验回发授权或工具不可用时，在所属窗口交付，由获授权方读取。通信由工具实际消息触发，不假定自动收件或后台监听；只交接结论、证据路径、责任和待决项，现有权威文件与 Git 保存持久依据，避免重复积累完整聊天历史。每个窗口负责其子代理并汇总。共享 checkout 的 Git 暂存和提交、同一清单/共享资产写入、受影响索引构建及 SQLite 同步由协调镜像协调串行；消息不是系统锁。无法确认写者已停止时，不写对应共享文件或进行相关共享 Git/索引写入，先核实并继续独立工作；等待超时不代表写入已停止。提交仅包含本阶段文件。

维护窗口按需提供具体结果，不反复复审已完成事项；只有用户明确的授权、真实阻碍或影响共享契约的变更需要跨窗口协调。汇报阶段、实际路径、验证范围、可用状态和剩余缺陷；不把 Windows 离线检查称为实车验收。
