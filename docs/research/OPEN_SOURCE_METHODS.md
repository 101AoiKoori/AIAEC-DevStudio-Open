# 国赛识别：开源项目比较与逐任务方法

研究记录始于 2026-11-03。研究基于规则说明、项目官方仓库及省赛代码；现有大量国赛场地和物料实拍图片、视频及小车摄像头照片，可用于参考、核对、参与训练及构造合成样本。部分视频已作为合成背景进入现有训练数据；用户允许训练、验证和测试复用同源素材，评估需说明复用范围；目前没有完整国赛模型验收、真实车载速度或完整依赖验收。本文维护已选择的开发主线；实验验证主线并修正实现，不以未做实验悬置方向。每个任务的规则与播报原文以 [统一任务配置](../../config/perception_tasks.json) 生成的 README 为准。仪表的更细分析见[独立研究](METER_VISION.md)。

## 共同原则

- 有省赛模型的任务，可用未参与训练和选模的来源组检查已有模型；实拍、实拍增强、实拍拟合渲染及场景合成按来源和生成方式分别记录，再以合成数据训练或微调；训练和推理分开，推理模块只有 `ws/src/aec_vision/` 一份。测试集不参与选模或调参，数据用途见[数据集设计](../DATASET_DESIGN.md)。
- 一张原始帧可服务多个任务，任务需要时才推理；静态任务在后台处理。采样不等待画面质量评分；交通灯和禁行牌分别保留实时决策门，详见[异步设计](../ASYNC_PERCEPTION_DESIGN.md)。
- 每次记录：任务、运行/观察点、来源图像、模型及配置版本、状态、框/读数、耗时、终端和图像证据；失败与空场景分开。
- 记录采集场次、设备和物料实例；按用户确定方案允许同源复用，评估时说明复用范围，并在具备独立测试来源时报告其整任务结果，而非只看模型 mAP。CPU 及小车推理依赖必须现场确认，不能用上游速度数字代替实测。
- 项目的源码许可、模型文件及数据许可可能不同。仓库声明只用于筛选，不等于其预训练权重和数据均可自由使用；Ultralytics 本身为 [AGPL-3.0](https://github.com/ultralytics/ultralytics/blob/main/LICENSE)，使用前核对团队实际分发条件。

## 1. A/B 街人偶与人数

**候选来源**：省赛人物识别方案 已使用二分类 YOLO，类别是社区与非社区人员，并返回原图坐标；需核实模型和省赛运行环境在国赛的适配。训练与推理框架参考 [Ultralytics](https://github.com/ultralytics/ultralytics)，但其通用行人类不能直接区分两种立牌。

**方法拆解**：① 由任务点写入街区 ID 和观察范围；② 单帧检测两类人偶，保留框、类和置信度；③ 为跨视角重复目标指定不重叠观察区域，或基于标注的对应关系做合并，不能仅凭相同类别合并；④ 每街分别保留两类数量，等 A/B 都完成后按任务配置中的两类合计公式汇总；⑤ 标注非社区人员并保存原图对应的框图，输出与播报。

**训练与评估**：使用已有 16 个社区人物和 2 个非社区人物图案、实景背景及电动车素材合成训练图，覆盖不同尺度和遮挡，并标注类别与可见框；现有实拍可参与训练、核对或形成合成场景基底；全部派生物按来源组划分，评估时核实街区和跨图关联。比较省赛权重与合成训练权重时使用验证集，冻结方案后在独立测试集统计每类漏检/误检、每街计数全对率、重复计数数、非社区框图正确率与完整汇总成功率。失败或未知街区不计为零；总人数公式及其依据由任务配置维护。

### 第一版执行流程（2026-11-06）

1. 观察请求明确 A/B 街、可见区域和覆盖段；取帧后保存原图。同帧可派生人物与违停作业，但两项使用各自模型，不能宣称共用一次推理。
2. 用独立训练的 YOLOv8 检测社区/非社区人偶，按原图坐标保存实例。整图分类不能承担人数统计。
3. 首版优先采用能完整覆盖的单帧或互斥观察分区；重叠时必须关联物理目标。不能用相同服装、类别或框的个数直接跨图合并；遮挡导致无法确认覆盖时保留部分完成。
4. 每街分别形成社区人数、非社区人数及覆盖状态，标注非社区人偶；只有覆盖完整且识别流程有效时，零检测才可作为零人数候选。A/B 结果齐全后按任务配置汇总两类总人数，分项和覆盖状态随结果保留。
5. 每街框图保存后进入输出队列，总汇总按依赖完成条件触发一次。晚到结果绑定原运行，不能重复加人数。

配置候选为街区观察范围、类别映射、有效阈值与跨图归属策略；不预设固定人数。验证重点是每街完整计数、非社区定位及遮挡下的失败表达。模型与裁剪按统一资源预算执行，四处以上观察也不得无界缓存原图。

## 2. 三个停车位的车牌

**优先基线**：省赛车牌检测、自研七字符 CNN OCR 与 PaddleOCR 双路组合，已开始迁移，详见[省赛双 OCR 迁移](PLATE_DUAL_OCR.md)。正式 Paddle 模型为 `PP-OCRv4_mobile_rec`。对照候选 [HyperLPR3](https://github.com/szad670401/HyperLPR) 官方 README 支持中国车牌及 Python/Linux，代码仓库声明 Apache-2.0，但目标车可安装的 Python 3.8 wheel、模型离线可用性和具体权利需另验证。

**方法拆解**：① 任务上下文带车位编号；② 全图检测牌框并回映到原图；③ 做带边距裁剪和必要的角度校正；④ 识别省份、字母、后续字符与可能的点；⑤ 使用已确认的字符集与长度检查；⑥ 每车位分别产生车牌字符串、框图、播报。单帧作为对照基线，短序列与平移视频作为开发候选，默认采样模式待实测选择；不同 OCR 的置信度不能直接认为可比较。

**训练与评估**：同一车牌实例的不同角度不要跨训练/测试集，收集小字、反光、不同颜色和易混字。分别报车牌框召回、整串全对率、字符混淆、小数/间隔符展示、三车位归属与最终播报成功率；新增车牌规则或八字符需求需现场确认。

## 3. 红绿灯

**选定方案**：用户确认省赛已完整验证 OpenCV HSV 色域与三条 ROI 方案可行，国赛沿用，无需训练检测模型。车辆经 waypoint 在等待线前以固定角度停车，在画面中部配置三条宽度可调、从画面顶部贯穿到底部的竖向长条 ROI，从左到右分别覆盖红、黄、绿灯位。现有车载实拍及规则示意支持水平灯位排列；两处国赛灯位的 ROI、色域和停车前后偏差分别校准，省赛参数不直接作为国赛标定值。

**方法拆解**：① 按观察点选择三条灯位 ROI；② 在对应 ROI 内做 HSV 阈值、连通域和亮区判断；③ 连续帧确认与过期撤销独立实现；④ 输出 `red/yellow/green/unknown` 和采集时间；⑤ 仅新鲜稳定绿灯可作为导航决策输入。红灯等待线与避障由导航方执行。更换相机视场要重新标定 ROI；不能只靠灯的时序猜灯色。长条可扩大沿其方向的覆盖范围，但不能保证任意停车位置或角度都能可靠识别。

**标定与评估**：使用两处灯的真实画面标定色域和三条 ROI，检查停车点前后偏差、三色切换、反光、背光、无灯和断流。报告红/黄误判绿次数、绿灯识别延迟、状态过期处理及并发后台推理时的延迟。车端时效须实际测量。

### 第一版执行流程（2026-11-06）

1. 到达等待线前的 waypoint 观察位置后激活对应灯组的三条长条 ROI，检查图像时间与灯位身份；两处灯分别标定位置、宽度和色域，不共用未确认的固定像素框。
2. OpenCV 在 ROI 内做 HSV 分割和连通区域分析，结合亮区位置与面积形成颜色候选。缺灯、多色冲突或位置不符输出未知，不能只取最高颜色分数作为绿灯。
3. 用有限长度的时间窗口确认稳定状态；绿灯需满足连续有效观测，新鲜度随时间失效。出现红、黄、未知或断流时撤销允许通行的视觉依据，不沿用此前绿灯；具体窗口和期限依实测配置。
4. 发布灯组、颜色、采集时间、有效状态和原因，导航在等待线前停车并处理通行。观察结束后关闭该段采样，下一灯组重新建立状态。已开始通过的路口如何运动由导航根据车体位置处理，识别节点不能独立发停车速度覆盖导航。

实时通道只保留最新必要帧与短窗口状态，丢弃尚未处理的旧实时帧不等于删除已接受的后台原始证据。与其他 YOLO 满载并行验证错误放行、断流、ROI 偏移与响应延迟；灯周期仅为规则背景，不参与推算放行。

**实现状态**：`aec_vision.traffic_light` 已提供需显式配置三色 ROI、HSV 色域及连通面积的单帧候选识别，以及独立的连续帧确认和过期状态器。颜色变化、未知、重复时间戳或停车位置未确认时撤销原状态；调用方须在断流时继续查询状态，并使用同一单调时钟。当前未接入 ROS、waypoint 或运动控制，国赛标定参数尚未提供；Windows 合成输入单元测试通过，不代表国赛现场验收。

## 4. 禁止直行牌

**检测对象**：用户提供的视频中的牌面、立杆与底座组成的实物作为一个检测类别，训练检测器识别该物体外观与画面位置。无需识别牌面图案或区分其他交通标志类别；输出中的禁止直行含义来自赛题和该实物的任务约定。视频同一物体从背面、侧面、正面环绕拍摄，其派生帧视为同一来源组。

**方法拆解**：① 以现场观察位置或全图检测单类牌具；② 根据实物参考合成目标框训练图，覆盖不同视角，并以无牌及外观相似物作为负样本；③ 结果带目标框、观察点和可靠状态；④ 经现场标定将目标位置映射到分支；⑤ 按任务约定输出、播报并交给导航方判断。未知时不能按允许直行处理。

**训练与评估**：现有牌具视频用于核对两种摆放位置、不同背景和相似物的合成覆盖，也可作为合成场景基底；同一视频及其派生物可按用户要求用于多个 split，结果需说明来源复用范围。分别测实物检出率、误检、左右/点位归属、两条分支决策正确率及未知情况下是否阻止错误通行。同一视频的相邻帧不能跨独立评估组。

### 第一版执行流程（2026-11-06）

1. 在分支选择发生前设置观察段，先通过已知观察位置与相机视野找到候选标志；首版采用针对国赛实物训练的轻量标志检测器，包含无牌和相似图案负样本。
2. 输出单类牌具检测结果、原图框和观察身份；依赛题约定播报禁止直行。根据牌的位置确定受限路段，不能只检测出实物就任意选择路线。
3. 通过现场标定的“摆放区域 → 受限路段 → 允许路线”配置进行匹配；无匹配或多个匹配均保持未知。图中两种摆位是配置依据，不是可直接使用的地图坐标。
4. 可靠结果交给路线协调器锁定该次决策并并行生成播报/图片；语音执行不应成为解除视觉门控的额外阻塞，但其输出仍须追踪完成状态。识别超时则保持在可等待位置，按有限重试策略处理，不能默认某条路线。

验证检测准确率之外，还需逐一验证两种摆位及未知情形对应的路线行为。结果重复送达不能触发重复切换；需要重新决策时显式创建新尝试。标志作业优先于普通后台计数，且不擅自替代导航路径规划。

<a id="waste_bin"></a>
## 5. 四分类垃圾桶及投放状态

**设计状态：颜色及规则判定核心已建立，独立模型和整链尚待实现与现场验证。** 任务规则、24 个图例及类别映射的编辑源为 `config/perception_tasks.json`，见[任务说明](../../lab/features/waste_bin/README.md)。用户确认只观察四桶正面，无需看桶内。本节维护算法与处理流程；路线与运动边界见[项目方向](../PROJECT_DIRECTION.md)。

### 第一版选择

采用“定位 → 分别识别 → 关联 → 查表判定 → 证据输出”。桶体定位由现场观察与后续实拍确定；对已定位的桶体区域用 OpenCV HSV 判断蓝、红、绿、灰并映射四类。用独立的 YOLO 垃圾贴模型检测并识别具体垃圾；用另一个独立 YOLO 二分类模型识别桶盖打开或关闭，输入覆盖桶口和盖板的裁剪。两个模型的数据、权重和输出各自管理，按目标机资源预算调度。

开闭分类输出打开、关闭或无法判断；无法判断由有效性与置信度规则产生，不强迫模型二选一。垃圾贴模型输出位置和名称或未知。桶类别与垃圾名称分别判断，投放正确与否由确定的类别映射计算，垃圾贴名称不依据桶色判断。

桶体颜色、盖板和垃圾贴分别处理，能检查每一步的有效性。灰色背景可能与灰桶混淆，颜色函数只接受已定位的桶体裁剪，阈值、光照、反光和遮挡须以现场相机标定；遮挡或颜色冲突输出未知。垃圾贴模型是否需要先检测再裁剪，以实拍小目标表现确定；桶盖 YOLO 保持独立二分类模型。

### 一次观察的完整流程

1. **采集与登记**：导航按所选路线提供观察身份和拍摄时刻，取得包含四桶正面及盖板的图像并保存；四桶同帧只是首个实验方案，实物样本证明贴纸太小时改用预先配置的分组观察。必要原始数据交接成功后后台处理，不让画质评分阻塞行驶。
2. **定位**：在原图确定桶体与垃圾贴范围，保留原图坐标和分数。桶体 ROI 的可靠获取方式由实拍验证；贴纸由垃圾 YOLO 定位。未发现某桶记为缺失，不凑齐四桶、不默认空桶。
3. **建立关联**：通过垃圾贴位于桶正面范围的关系归属到桶。贴纸同时落入多个重叠桶框或位置不合理时记录歧义，不简单用最近框中心决定；多贴、缺贴分别记录，不默认现场一定一桶一贴。
4. **独立识别**：逐桶使用桶体颜色判断类别，独立盖板 YOLO 判断开闭，垃圾 YOLO 判断贴纸名称；陌生图案、遮挡、低可信度和相互矛盾均保留未知，不能仅取最高分就视作有效。
5. **查表判定**：名称有效且存在已确认映射、桶类别有效、关联唯一时，比较两者，输出正确或错误。开闭未知不阻止有效的投放判断；垃圾未知不阻止有效的开闭输出。多贴的聚合口径未确认前保留逐贴结果并将该桶投放汇总标为待定。
6. **跨观察合并**：依据观察区域、桶类别和位置对应关联同一物理桶。不同帧结果冲突时保留来源，不覆盖成最后一次结果；分类名称单独不足以证明是同一桶。首版优先互斥分组观察，确有重叠再实现关联融合，不直接累加检测框数量。
7. **输出与结束**：输出图标注桶框、垃圾贴框、开闭、名称及投放结论；采用原始帧绘制，裁剪坐标需正确还原。按桶汇总终端与播报，完整成功需所需输出和证据均完成。未知字段明确报告未识别，不插入假定名称或正确结论。

建议结果记录包含运行/观察/桶实例 ID、来源帧、桶框、桶类别及状态、盖状态及状态、垃圾贴列表（框、名称、归类、有效状态）、投放结论、失败原因及输出状态。此为接口设计，尚未新增 ROS 消息或实现对象。四桶独立汇总，已完成项可输出，其他项保持部分完成；重复事件不重复播报。

### 数据与配置边界

合成训练图并标注桶框及四类桶身份、完整盖板区域与开闭状态、垃圾贴框与名称、贴纸到桶的归属。组合正确和错误投放，确保同一垃圾贴出现在不同颜色的桶上；覆盖开闭、倾斜、反光、遮挡、不同距离、缺贴及陌生图案。开闭训练集不能让某种桶颜色只对应一种盖状态。现有实拍用于参考、核对，也可参与训练或生成合成样本；实拍及其派生图可按用户要求用于多个 split，结果需说明来源复用范围。

第 12 页参考图可用于建立标签和辅助素材，不能替代实际相机样本。按采集批次、视角和实物记录验证数据；同图增强或相邻视频帧跨训练与验证时，结果说明同源范围，不作为独立采集结论。垃圾名称与分类以任务配置为唯一映射源，未来训练和 ROS 的可执行映射从该源生成或引用。

`aec_vision.waste_bin` 提供候选 HSV 桶色分类、贴纸与桶框唯一关联、规则查表判定；调用方提供可信 ROI、YOLO 结果及有效性。候选阈值需校准，灰色只在已确定的桶体 ROI 使用。检测与分类模型、贴纸/桶体自动定位、盖状态、ROS 输出及播报尚未实现；训练配置留在 `lab/features/waste_bin/training/`，正式运行配置与共享推理核心放在 `aec_vision` 包内。

用户提供的四桶照片用于一次 Windows 离线抽查：分别人工裁取四个桶体，蓝、红、绿、灰各 1 个 ROI 均匹配相应类别。该图没有用于核验垃圾贴或盖板模型；单图、人工 ROI 的结果不足以设定现场验收结论。

### 资源与验收顺序

同一原图通过引用服务所有子任务，逐桶或有限批次裁剪并推理；完成裁剪使用后释放图像和张量引用。原始图、必要标注和结果按统一生命周期保存；模型由统一执行器管理。关闭状态不跳过垃圾贴分支，单个分支失败不取消其余仍可完成的分支。接入[异步调度](../ASYNC_PERCEPTION_DESIGN.md)时给每次观察明确截止时间与输出状态。

先验证正面图能同时提供盖板与垃圾贴信息，再依次测定位、开闭、垃圾名称、关联、投放和每桶完整输出的正确率。单独统计错误投放被误报正确、未知样本被强行分类、缺桶及重复归属。随后在两条路线对应视角上测试整组与分组采样，最后测导航并行时的峰值内存、推理耗时和证据保存耗时。验收阈值与速度由样本和目标机实测决定，目前不宣称满足比赛精度。

## 6. A/B/C 楼火灾隐患计数

**候选来源**：[fire-smoke-detect-yolov4](https://github.com/gengyanlei/fire-smoke-detect-yolov4) 提供火烟数据和旧检测参考，仓库声明 MIT，作者提示原代码停止更新；其真实火焰和烟雾域与比赛模型楼宇的隐患物料是否一致尚未确定，不可把真实火焰权重当现成比赛方案。

**方法拆解**：① 定位楼顶纸条并读取自定义名称；② 检测火焰贴纸并以观察区间和画面分区关联名称；③ 多视角采用分区或目标关联去重；④ 单楼输出读到的名称、隐患数量与框图。名称、归属或覆盖不可靠时分别标记未知或未完成。A/B/C 是观察身份，与摄像机读取自定义楼名并行使用；火焰贴按宽 2.5 cm、高 3.5 cm 设计。

**训练与评估**：标注楼名纸条位置与全文、火焰框及跨帧归属；加入无隐患、光照变化、文字和反光负例。评估完整名称、目标级漏/误检、每楼计数全对率及名称与火焰归属。实景和采集边界见[数据集设计](../DATASET_DESIGN.md#场景证据与楼宇采集)。

**楼名 OCR 对照**：比较 PaddleOCR 和 [EasyOCR](https://github.com/JaidedAI/EasyOCR) 的中文文字识别。EasyOCR 项目代码声明 Apache-2.0，支持简体中文，官方说明采用 CRAFT 检测与 CRNN 识别；实际使用的权重许可、版本及目标环境兼容性须逐项核实。当前以 PaddleOCR 为现有接入基线，新增 EasyOCR 作为明确替换候选；软件先按可替换第二 OCR 接口继续开发，楼名和车牌分别验收。同一引擎能读中文楼名不自动证明可承担车牌第二路。两者先用同一人工标注裁剪图比较识别，再以同一原图比较各自完整定位与识别链；分别报告完整名称准确率、字符错误率、漏检/不可读、错字、失败及各条件样本数。固定同一真实验证集、文字真值、预处理、硬件和计时口径，记录版本、模型、语言、参数及输入；另测初始化、每图延迟、内存和离线运行。名称不得预设为固定词表，报告未见名称表现。验证集用于选方案，冻结后只在独立测试集评估。技术文档如实引用逐样本结果、方法与限制；当前尚无对照实验结果，第二引擎替换待决定；模型输入、结果与资源配置先按可替换契约设计。

### 第一版执行流程（2026-11-06）

1. 按观察位置获取包含指定贴纸面与楼顶名称的原图，记录观察实例与覆盖范围；定位名称纸条并用中文 OCR 读取完整文字，支持自定义楼名。
2. 用火焰检测器检测实际比赛贴纸；整图或按现场观察区域裁剪的效果由实拍对照，裁剪需保留坐标映射与足够覆盖。
3. 按观察上下文、视野分区及跨帧对应将火焰关联至名称；多楼同框、遮挡或边界导致归属不清时标记未完成。
4. 每栋楼汇总去重后的实例；分组观察需互斥空间归属或目标对应，不能将重复视角的数量相加。
5. 原图框选隐患，输出并播报实际识别出的楼名和数量；名称识别失败标记未知，覆盖未完成或推理失败不得输出零。三楼分别完成。

训练数据需包括密集小目标、无隐患、楼宇文字和反光干扰；按每楼计数全对率与归属错误率评估。OpenCV 颜色/形状仅作为后续对照，不根据红色面积直接计数。候选模型由协调器轮流加载或有限驻留，不为每栋楼再启动一份模型。

## 7. D 楼热异常楼层

**已明确的输入**：一个红外设备，D 楼为三列四层，中列一根竖直发热电阻，两侧列不发热；赛方只要求说明异常楼层。按理想硬件提供有效热图设计，设备参数作为接口配置输入，不阻塞算法。

**确定流程**：定位 D 楼与四层区域 → 配准红外与可见光／楼体坐标 → 提取中央热源带及热异常区域 → 按层统计相对热响应 → 形成异常楼层集合 → 框选并播报。D 楼可通过可见光实物检测或已标定的固定观察区域定位；具体可靠方式待红外设备到位后检查。

1. 标定红外设备和可见光相机的图像坐标、内外参、安装关系与时间对应，定位 D 楼外轮廓、楼底、楼顶及四层边界；记录观察位姿、楼体高度及楼层编号方向。对已知同一楼面上的对应点先估计红外到楼面或可见光的二维仿射变换；若透视显著且仿射残差超限，使用平面单应性，配准不可靠时输出未知。上述映射只适用于经过标定的共同楼面，不能单靠二维仿射推断任意三维空间坐标。
2. 各层在中央带统计热响应，以同层背景及冷态参考计算相对变化，配合有效面积排除孤立噪点。传感器提供温度值时使用温差；仅图像强度时保留强度单位，不编造摄氏温度。
3. 竖直电阻的热区可能连通或传导跨层，按每层 ROI 独立判断；热连通块数量不能作为异常楼层数。两侧列的冷区用于背景，不作为额外待分类位置。
4. 将热异常区域映射到楼面局部坐标，以实测楼底和逐层边界或经核验的楼层高度划分四层；等层高仅为缺少逐层实测时的待验证近似。只有已知相机位姿及楼面与地图坐标的标定关系时才换算全局坐标，否则保留楼面局部坐标及未知状态。按热区与各层的交叠分别输出四层状态及异常楼层集合，不固定只报最热一层；热边界或有效数据不足的层标未知，其他已确定楼层继续输出。
5. 保存原始热图、层 ROI、中央热响应与阈值配置，在红外图框选热点及对应楼层，按楼层播报。

**待解决**：红外硬件尚未到位，设备型号、原始数据形式、配准误差及阈值均未测定；冷态/热态相对阈值、热扩散边界、楼层边界与有效面积参数需依据设备数据确定。按同一硬件配置的冷态、升温、稳定及冷却采集轮次分组，记录真实异常楼层，检验逐层漏报/误报和全楼结果。电阻具体可控制方式、同时异常层数不作先验限制；当前仅记录方案，不声称已实现或验证。

**下一批采集**：在同一观察位置采集完整楼体红外图，记录设备型号、分辨率、距离、时间戳及四层编号；分别采集未加热、升温、稳定和冷却阶段的红外视频，每阶段建议至少 10 秒。记录电阻实际通断、通电与断电时间、可确认的加热部位和异常楼层真值；无法确认时留未知。若加热部位不可单独控制，记录实际控制方式。采集分批保存，避免同一轮相邻帧跨训练与验证。

**待全局规划**：观察段、输入时间戳及楼体映射接口。先用热图和楼层配置实现上述流程，联调后接入真实消息。

## 8. 非机动车违停与倒伏

**候选来源**：[Ultralytics 检测框架](https://github.com/ultralytics/ultralytics) 可训练电动车/其他非机动车检测，但通用检测类别本身不输出“违停”或“倒伏”。不同赛场其他样式待专家会议确认；没有经证实的开源权重可直接覆盖该场景。

**方法拆解**：① 观察点或配置提供 A/B 街与停车区身份；② 检测所有现场纳入统计的车辆；③ A/B 街分别判断违停有无，直立或倒伏电动车均表明该街存在违停；④ 停车区按车辆级去重并汇总总数与倒伏数，姿态不明单独记录；⑤ 按区域播报。仅在姿态均已确认时可用总数减倒伏数得到正常数。矩形框宽高比可能受视角影响，不能单独当作可靠倒伏规则。

**训练与评估**：标注车辆类别、区域、状态、框与跨图身份，覆盖不同车辆、遮挡、车头朝外、倒伏朝向和区域边界。分别测车辆召回、区域归属、姿态混淆、去重误差和四项统计全对率；街区边界及其他样式非机动车是否计分须现场确认。

### 第一版执行流程（2026-11-06）

1. 请求区分 A 街、B 街与停车区；每个观察或扫描有独立身份与覆盖区。三处不能混合计数，其他非机动车是否纳入按现场物料口径确认。
2. 独立 YOLO 检测车辆及正常/倒伏姿态，保留不确定类别。A/B 街分别判断违停有无，人物立牌区域内只要有电动车即存在违停；停车区统计总数与倒伏数。区域归属不明时保留未知。
3. 确定主线为沿允许路径平移并配合转向的短扫描，分段记录视频后按时间顺序流式处理。首版采用带相机运动补偿的 BoT-SORT 维护关联；实体计数状态独立于跟踪器 ID，沿既定主线修复错连和断连。
4. 建立物理车辆记录，跟踪 ID 仅为关联线索；遮挡重现、跨片段、返回重扫都可能换 ID。结合时间、位置和外观关联，无法确定则标记计数歧义。地面定位需可信标定和接地点，不能直接把框中心映射成停车位置。
5. 同一车辆多帧汇总姿态，跨区域归属冲突单独记录。按各街是否存在违停、停车区总数与倒伏数分别汇总；未完整覆盖时不把未见目标当无违停或零。姿态不明不抹去已确认的总数，倒伏数按实际状态标记未知或部分完成。
6. 保存逐车来源帧和框图供复核，按区域输出已完成结果。关键证据帧可从已保存视频中提取，运行内存仅保留有限帧和轨迹摘要；扫描结束后关闭关联上下文。

计数按扫描实体表提交，短时暂失保留身份，明确出界或扫描闭合后提交一次；重扫先关联已有实体，歧义不静默加数。验收分别检查漏计、重复计数、姿态与区域归属，以及不同扫描速度下最终四项统计的正确性。具体跟踪实现需固定兼容目标机的版本，当前尚未接入。
