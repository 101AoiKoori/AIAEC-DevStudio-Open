# 省赛车牌双 OCR：迁移与使用

## 实际来源

比赛使用省赛 YOLO 检测器、混合数据微调的七位置 CNN 和 `PP-OCRv4_mobile_rec`，正式模型与仲裁见[比赛双 OCR 决策](#本次比赛双-ocr-决策)。两路处理同一车牌裁剪图并分别保留文本和分数。

对照策略 `province_baseline`：两路规范化文本一致则接受；不一致时，合法七位 Paddle 文本且其自身分数达到 0.70 则采用 Paddle，否则保留 CNN。省赛确认流程为单牌画面最多三个有效帧、相同结果至少两票；选帧时跨 OCR 比分的可比性尚未校准。CNN 分数为七个分类头最大概率的平均，并非整串正确概率。

## 已迁入

共享推理核心：[plate.py](../../ws/src/aec_vision/src/aec_vision/plate.py)，正式参数：[inference.json](../../ws/src/aec_vision/config/plate/inference.json)，七位字符顺序：[charset.json](../../ws/src/aec_vision/config/plate/charset.json)。包括：

- 自研 CNN 的五层卷积和七个位置分类头；输入尺寸从权重读取，省赛权重为 224×64。BGR 裁剪后按省赛流程转 RGB 并归一化。
- 本地 PaddleOCR 识别器及两路独立结果、各自分数、最终采用来源。任一读取器运行异常时返回 `error`。
- 正式配置采用 `cnn_primary`；`agreement_only` 与 `province_baseline` 用于对照实验，详细规则见[比赛双 OCR 决策](#本次比赛双-ocr-决策)。
- `confirm_plate_samples` 默认处理单帧单票，省赛 3 帧 2 票可显式设置作为对照。它接收已采集、已推理的结果，不负责相机、等待、图片保存或播报；配置文件中的投票参数尚未接入调度器，也不会自动采集。当前函数仍沿用省赛“一个画面恰好一块车牌”的筛选；一张图同时出现多车位时，须先设计车位与检测框匹配，不能直接用于该场景。
- [train_cnn_ocr.py](../../lab/features/plate/training/scripts/train_cnn_ocr.py) 依据省赛微调训练流程的模型、标注格式、训练参数和轻量增强整理；网络直接复用共享推理核心。支持 CPU 冒烟与 CUDA 训练，配置和能力边界见[结构对照训练](#cnn-结构对照训练2026-11-06)。

三个模型已放在本机 `ws/src/aec_vision/models/`：`plate_detector_best.pt`、提取推理所需字段的 `plate_ocr_best.pt`，以及 Paddle 的 `inference.json`、`inference.pdiparams`、`inference.yml`，全部直接放在该目录，不设子目录。按照工作空间约定，模型不进入 Git；该目录需要随 ROS 包单独传到小车。Paddle 模型名为 `PP-OCRv4_mobile_rec`。

数据组成：

- CCPD 检测图 15,495 张，train/val/test 为 10,796/1,899/2,800，标注一一对应；来源统计记录 14,500 张正样本和 995 张负样本。
- CCPD OCR 裁剪图 14,500 张，train/val/test 为 10,000/1,800/2,700，文本为 `相对图片路径<TAB>号码`，裁剪尺寸记录为 168×48。不能与 224×64 的最终 CNN 输入尺寸混淆；训练加载时需显式预处理。
- `detection/ocr_external/yolo_crop/` 另有 500 张从 test 图片经检测器裁剪的图片，只作测试，禁止混入训练、早停或调参；它与原 test 有来源重叠，不能再算一套独立测试集。`gazebo/` 当前只有说明，没有图片。
- 第一轮合成检测为 1,725/192 张训练/验证图，OCR 为 6,200 张，按 JSON 标注拆成 5,580/620；OCR 图片物理上全部在 `images/train/`，必须按标注划分，不能按目录名判定 split。
- 第二轮合成检测为 2,000/400 张训练/验证图，每图三车牌。训练合并第一轮，验证仅第二轮固定场景；不能用该验证成绩证明真实场景泛化。

OCR 的“全面”应拆成字符表覆盖和实测分布：七头 CNN 支持 31 个省份字符、24 个第二位字母及后五位各 34 类，只支持七位格式；八位新能源车牌及特殊牌型不在该网络输出范围。原检测来源统计中“皖”占正样本 13,442/14,500（约 92.7%），字符表存在不代表少见字符已得到充分训练。后续以合成数据覆盖字符和场景训练；实拍及实拍派生数据按来源组评估，分别报告字符、角度、远近和反光条件。

Paddle 版本核对以部署配置和模型元数据为准，当前为 `PP-OCRv4_mobile_rec`；引入其他版本时须同步验证加载器与输出格式。

导入保留原始标注与配置，排除可重建的 `.cache`。原始数据配置中的相对路径和旧来源路径需按本机数据根目录解析；`train_cnn_ocr.py` 支持 CCPD TXT 与微调 JSON 标注，路径以标注文件或项目根目录解析，详见[结构对照训练](#cnn-结构对照训练2026-11-06)。

本次复制共 60,858 个文件、1,624,771,573 字节（约 1.51 GiB）。离线检查通过：三套检测数据图片/标签对应、类别为 0、归一化坐标范围合法；两套 OCR 标注均能找到图片且文本为七位；各数据集 split 内无重复名称、split 间无同名交叉；500 张外部测试裁剪引用有效。未做全量图片解码、视觉近重复检测或人工真值复核，名称无交叉不等于没有同源泄漏；尚未在实车上验证。

```bash
python lab/features/plate/inference/tests/run_plate_image.py datasets/raw/plate/待测图片.jpg
```

```bash
python lab/features/plate/training/scripts/train_cnn_ocr.py --config lab/features/plate/training/config/cnn_ocr.json
```

训练和验证集应按车牌物体、采集批次划分。输出是最佳验证整牌准确率对应的模型文件；将选定的新权重部署为推理使用的模型后，须在国赛数据上重新评估。模型与字符表位置顺序必须一致。

## 本次比赛双 OCR 决策（2026-11-07）

部署 CNN 为混合数据微调的 `legacy` 七头结构，来自 `legacy_control_20261106` 的 epoch 9：CCPD 验证整牌准确率 86.56%、合成验证整牌准确率 97.26%。选型依据见[结构对照结果](#本轮结果与决定)。

正式策略 `cnn_primary`：

1. 两路都生成字符表内的七位号码且完全相同，采用号码，记录 `agreement`。
2. 微调 CNN 输出合法七位字符串时，CNN 为比赛主输出。若 Paddle 也合法但文本不同，采用 CNN 文本、状态保留 `ok`，决策明确记为 `cnn_primary_disagreement`，同时保留 Paddle 文本及两侧分数供审计；这表示政策选定的模型结果，不代表已由第二路确认。
3. CNN 文本不合法时，只有合法 Paddle 文本且其自身置信度达到 0.70 才使用 `paddle_fallback_cnn_invalid`；否则为 `unknown`。若读取器抛出异常，仍返回 `error`，不伪装为正常单路输出。
4. 从不直接比较 CNN 与 Paddle 的置信分数。Paddle 分数只与自身既有 0.70 门槛比较。

当前端到端回归仅覆盖下述两张合成验证图，样本量不足以校准错误概率或证明实车效果。批量播报前须验证同车位同目标的多帧整牌一致性及现场实物表现；多帧仲裁和实车调度尚未实现。

## CNN 结构对照训练（2026-11-06）

实验复用 [train_cnn_ocr.py](../../lab/features/plate/training/scripts/train_cnn_ocr.py)，沿用七位字符表、RGB/255、轻量旋转与亮度/对比度/模糊/JPEG 增强、AdamW、warmup/cosine、AMP 和整牌验证指标。入口保存最佳推理检查点及逐轮 JSON 指标，完整断点续训与 TensorBoard 尚未接入。

候选 `spatial_v2` 定义在共享 `plate.py` 的 `create_cnn`，保持原五层卷积和七个分类头；新增 256 通道 depthwise 3×3 → BN → ReLU → pointwise 1×1 → BN 的残差细化层，将原 `(1,7)` 平均池化改为 `(2,7)`，每个头读取上半/下半各 256 维与全局 256 维。这个改动试图保留字符上下结构，**尚不能据结构推断它一定优于旧模型**。残差思想参考 [He 等原论文](https://arxiv.org/abs/1512.03385)，定尺寸池化行为见 [PyTorch AdaptiveAvgPool2d](https://docs.pytorch.org/docs/stable/generated/torch.nn.modules.pooling.AdaptiveAvgPool2d.html)；具体组合为本项目候选，不是论文复现。

初始化从同一省赛检查点迁移卷积与分类参数：旧局部特征对应权重平分到上下两部分，全局权重保留，残差末层 BN 的缩放初始化为零。224×64 输入下，新结构在训练前与旧结构 logits 数值一致（浮点容差内）；训练后可以学习上下差异。检查点显式写入 `architecture`，加载器按字段选择结构；没有该字段的旧检查点继续按 `legacy` 加载，未知结构明确报错。

[cnn_spatial_v2.json](../../lab/features/plate/training/config/cnn_spatial_v2.json) 固定本轮实验：训练 CCPD 10,000 张与合成 5,580 张；验证分开报告 CCPD 1,800 张及合成 620 张，按两者整牌准确率的等权平均选最佳，不使用素材图选择模型。训练/验证检查路径无交叉，尚不保证无视觉同源泄漏。两种结构使用相同种子、数据、增强、优化器和最多 12 epoch、4 epoch 无提升早停、每组 25 分钟的 epoch 边界时间上限，batch=64，在 RTX 4060 Laptop GPU 上顺序执行。新模型只存训练实验 `runs/`，不覆盖 ROS 权重。

测试集（CCPD test 2,700 张和其中来源重叠的 detector crop 500 张）仅在选择权重后评估；后者不能与前者合并当成 3,200 个独立样本。省赛初始化权重可能已接触过旧验证素材，因此所有离线成绩都是已知来源上的对照，不代表国赛泛化。

```powershell
& .venv/Scripts/python.exe lab/features/plate/training/scripts/train_cnn_ocr.py --config lab/features/plate/training/config/cnn_spatial_v2.json
& .venv/Scripts/python.exe lab/features/plate/training/scripts/train_cnn_ocr.py --config lab/features/plate/training/config/cnn_spatial_v2.json --architecture legacy --output lab/features/plate/training/runs/legacy_control_20261106/best.pt
```

输出目录已存在时训练拒绝覆盖。使用 `--evaluate-only --weights <选定检查点> --split test` 执行冻结测试。训练前已通过新增结构初始化等价、可训练梯度、推理加载分派与旧权重兼容三项测试，以及现有双 OCR 十项测试。

### 本轮结果与决定

两组均完成 12 epoch，逐轮训练及验证累计耗时分别为旧结构 108.05 秒、新结构 109.16 秒，不含加载、首次验证和进程退出。训练使用本仓库 `.venv` 的 PyTorch 2.2.2+cu121。按事先确定的等权验证指标选中旧结构 epoch 9、新结构 epoch 10，然后冻结权重评估测试集，没有根据 test 再调整参数。

| 模型 | CCPD val（1800） | 合成 val（620） | CCPD test（2700） | 检测裁剪 test（500，同源） |
| --- | --- | --- | --- | --- |
| 原省赛 CNN | 66.44% | 96.13% | 56.59%（1528/2700） | 25.60%（128/500） |
| 原结构混合数据微调 | 86.56% | 97.26% | 83.33%（2250/2700） | 47.40%（237/500） |
| spatial_v2 混合数据微调 | 86.33% | 97.74% | 83.11%（2244/2700） | 47.60%（238/500） |

表内都是整牌正确率。新结构相对同数据重训的旧结构，CCPD test 少对 6 张、检测裁剪 test 多对 1 张，单种子结果不足以证明结构优势；显著改善主要见于两组共同的混合数据微调。新结构参数由 1,957,089 增至 2,484,705，检查点约 9.51 MiB（旧结构约 7.49 MiB）。

比赛选用 `legacy` 混合数据微调权重。`spatial_v2` 在同条件对照中未显示明确收益且参数量更大，作为可训练的研究候选保留。检测裁剪集仍不足 50% 的整牌正确率，说明仅对规整裁剪重训不能解决端到端鲁棒性。该观察尚不能单独证明具体错误原因；需要独立拍摄和人工标签，不能围绕这 500 张已查看测试图继续调参并把它们当未见测试集。

本机对照权重与 `run_metadata.json`、`metrics.jsonl` 位于 `lab/features/plate/training/runs/{legacy_control_20261106,spatial_v2_20261106}/`，冻结的省赛测试评估结果位于 `lab/features/plate/inference/outputs/cnn_comparison_20261106/comparison.json`，均保持 Git 忽略。正式 CNN 是 `legacy_control_20261106/best.pt` 的推理副本，部署位置为 `ws/src/aec_vision/models/plate_ocr_best.pt`。


## 国赛观察与融合流程（2026-11-06，待实现）

1. 任务提供运行、观察/扫描和车位上下文。设计主线为平移转向视频扫描，单帧用于识别核心调试；视频按片段保存并登记时间范围，后台按序读取。
2. 检测牌框并关联物理车辆和车位。多牌同框时先分配车位再裁剪，不能将整图直接交给现有单牌确认函数；归属无法确认的牌保留未知车位。
3. 每个裁剪交给 CNN 与第二 OCR（当前 Paddle），两路原始文本、分数、异常与仲裁来源完整记录；不使用一方分数替代另一方置信度。字符规范只允许已确认的展示转换，不能猜字补齐。
4. 同车位同目标的多个时刻形成候选集合，优先统计完整字符串一致性，避免逐字符投票拼出从未识别到的号码。支持票来自哪些帧、是否同一时刻重复推理必须记录；相邻帧高度相关，不能据票数直接宣称概率。
5. 对照单帧双路一致与明确配置的多帧策略，确认支持次数、采样间隔和冲突处置后再选择默认值；省赛三帧两票只作实验参数。双路一致也可能共同识别错误，需按完整车牌真实标签评价。
6. 每个车位输出完整号码及原图框，证据必须来自支持该号码且对应该车位的帧。到期仍分歧则标记未识别，不用其他车位补齐。

模型复用与加载交给统一资源协调，逐裁剪或有限批次执行，不默认双 OCR 并行更快。原始视频保留到相关证据与输出完成，候选记录存帧引用而非无限保存裁剪数组。测试同时检查完整号码、车位绑定、证据对应、峰值内存与总耗时。实现状态与函数边界见“已迁入”章节。


## 第二 OCR 可替换设计（2026-11-09）

事项状态见需求源中的 PLATE-1、PLATE-2、PLATE-3（[生成文档](../../lab/features/plate/README.md#状态与提醒)）。自研 CNN 保留，第二路 OCR 作为可替换识别器。楼名任务新增 OCR 引擎后，可能统一技术栈并替换当前 PaddleOCR；当前源码和正式配置仍使用 Paddle，替换仍待实现与验收。

第二路读取器统一返回引擎/模型版本、原始文本、规范化文本、该引擎自身分数与状态；适配到现有双路仲裁前核对字符集、七位格式、输入颜色空间和异常行为。任何替代引擎须重新确定自身分数门槛，Paddle 的 0.70 不自动迁移。正式返回字段替换要同步调用者与证据记录，不能让 EasyOCR 结果仍标为 Paddle。两路误差、CNN 主输出和冲突记录保持可追溯。

楼名与车牌是否共用进程/模型实例由输入、模型能力和资源调度决定。中文楼名全图检测与车牌裁剪识别是不同契约，可共用引擎而保留不同模型与预处理。优先实现两任务可替换的薄适配，不增加无关插件框架；替换验收针对两任务的固定输入与完整输出分别进行。
