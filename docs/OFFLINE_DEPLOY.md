# 双电脑离线开发与部署

开发机联网运行编辑器和 agent，使用 Git 管理代码；连接机连接小车网络，通过 NoMachine 操作 Ubuntu。两台电脑可用 U 盘交接文件。小车无需联网，也无需安装 agent。

连接机已经测试可以将文件拖入 NoMachine 会话。日常交付直接将开发机上的 ROS 包文件夹带到连接机，再拖进小车的工作空间。小车工作空间的实际位置和已有包需要现场确认，正式包建立后再固定具体路径。

在小车 Ubuntu 中进入现场确认的 catkin 工作空间，运行 `catkin_make`，然后执行 `source devel/setup.bash`。启动命令必须对应实际存在的入口；当前 `aec_vision` 尚无 ROS 节点或 launch 文件，不能仅靠构建声称已可启动整套识别。模型权重需要时单独传入，构建通过也不证明模型齐全或可加载。

交付前同时检查包声明和实际导入依赖。当前包声明不包含车牌推理使用的全部框架，需依据实际启用功能核对 PyTorch、PaddleOCR、Ultralytics 等及其目标机兼容版本，不能把开发机虚拟环境直接复制为 Ubuntu 环境。硬件和接口的已确认信息见[实车接口记录](HARDWARE_INVENTORY.md)；未填写项保持待测。离线交付与验收使用 `.agents/skills/workspace-offline-delivery/SKILL.md`，分别记录 Windows 离线、Ubuntu 目标机、ROS 集成和实车证据。

每次完成独立开发阶段后提交 Git，记录提交信息和实车测试结果。需要回到之前的代码时使用 Git。实车的图片、日志、地图和测得的坐标通过同一条文件通道传回开发机，用于下一轮开发。

没有仿真地图时，先用采集的图片、视频或 rosbag 验证识别和状态机，再分段测试真实导航、停车线、禁行分支和泊车，最后进行完整路线计时。
