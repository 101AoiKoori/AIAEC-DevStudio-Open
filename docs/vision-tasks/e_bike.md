# 电动车定位、街区有效车与停车区姿态

## 定义与作用范围

**分类：实例检测、遮挡关系与区域计数。** A/B 街区和停车区使用同一种物理目标，但交付量不同。街区逐辆确认有效车，业务层按街区报告是否出现违停候选。VisualRecognition 的街区研究口径以 `valid_bike` 为单类，不输出姿态。人与车重叠时，车在前方才计为有效车。停车区按有效观察区逐车统计总数及倒伏数，姿态不能确认的车辆仍可保留已确认的实例证据。DevStudio 历史需求还涵盖区域与跨视点去重。具体观察区域与遮挡规则分别追溯各自工作区，不能用同一组标签替代两个任务。 [任务矩阵](../TASK_MATRIX.md) · [VisualRecognition 任务定义](https://github.com/101AoiKoori/AIAEC-VisualRecognition/blob/main/e_bike/task.yaml)

停车区检测与倒伏判定由另一小组负责。本页的停车区内容保留本组历史方案和研究证据。**现场采用方法与验收记录：待负责小组补录。**

## 核心问题与可观测证据

在低机位，前后车辆可能投影到相近像素。地点与颜色相同也无法证明两个框指向同一辆车。姿态的物理依据是车架与地面的朝向和支撑关系，可用线索包括轮组、车篮、车身连续轮廓及其与地面的接触。街区有效性的线索是遮挡处轮廓的中断方向，例如立牌轮廓连续而车架轮廓被切断，支持立牌在前。从格式塔的良好连续性看，这些线索有助于把多段轮廓归回同一对象。接近的黄色碎片仍可能分别来自反光、头盔和两辆车，复核时需要轮廓、部件归属或邻帧证据。

历史框级方法的两个错误方向相反。重叠抑制过强会删除相邻真车，过弱会重复保留同车局部。Soft-NMS 以分数衰减保留重叠候选，CrowdDet 允许一个提案输出多个实例，都是密排问题的比较依据。二者的原论文结果来自各自数据，本组只对 Soft-NMS 做过有界参数试验。 [Soft-NMS，Bodla 等，ICCV 2017](https://arxiv.org/abs/1704.04503) · [CrowdDet，Chu 等，CVPR 2020](https://arxiv.org/abs/2003.09163)

## 数据与方法设计

- **实拍定口径。** 低机位车载原帧决定可用分辨率、相对尺度、地面接触、阴影、反光与画边截断的实际分布。原尺寸和邻帧帮助辨认头盔、倒影和被遮挡车体。相邻帧可用光流传播候选框，人工或逐图复核负责确认实体、裁边和遮挡标签，不能将传播失败等同于空场。
- **分层控制合成。** 历史方案以旋转实拍和分割车体裁片提供真实车型、颜色与部件外观，复用实拍场景和 Blender 机位底图。Python 按透视和接地摆放车体，联动可见掩膜及框，并形成单辆/多辆、远/近、朝向、姿态和彼此遮挡的组合。街区合成还可保持同一背景和物体，反转人与车的前后层次，仅改由此决定的有效车标签。此类配对可检查模型是否依赖颜色、位置或车数捷径。二维合成难以还原反射、接触阴影和相机视角变化对应的真实三维车体遮挡，实拍优先补这些缺口。 [DevStudio 接地合成入口](../../datasets/scripts/e_bike/compose_v4_grounded_train.py)
- **按来源解释指标。** 整帧、裁片与邻帧继承父视频和片段归属，同布局的镜像、改姿态和深度反转配对保留同源家族。独立验证按物理布置或采集段分组，开发回归允许已知布局但需记录接触。按固定有效区域、逐车匹配和任务业务指标分别比较。 [文献索引](../research/VISION_TASK_REFERENCES.md)

## 障碍、取舍与验证

停车区历史方案可以细化到部件配对或检测后验证，但这会增加标注、推理和错误归因成本。固定任务点下，改善视角和同画面内实例分离，可能比增加模型分支更合算。DevStudio 固定旧权重把输入从 640 放大到 960 或 1280 未带来旧开发集净收益，说明扩大输入需要随数据和部署预算共同验证。现场采用由负责小组决定。

街区从复杂两态输出缩成 `valid_bike` 以后，姿态监督成本下降，训练难点转为前后遮挡和真实机位迁移。验证应分报目标级漏检、误检、同车重复及街区有无误判，单列人挡车、车挡人、远端密排、反光及画边截断。停车区研究应另报逐车匹配和姿态、区域覆盖及总数/倒伏数；漏一辆同时多报一辆可使总数碰巧正确。现场输入区域未看全或推理失败时，保留未完成或未知状态，不发布确定的零辆。 [历史指标与错误分析](../research/E_BIKE_COUNTING.md)
