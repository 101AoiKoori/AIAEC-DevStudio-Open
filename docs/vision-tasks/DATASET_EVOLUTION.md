# V1–V4 数据集演进路线

国赛视觉数据的推进经历了四个阶段：先确定识别问题和可行输入，再低成本验证工程链路，随后扩大到任务级完整训练，最后依据现场失效重新组织规模化生产。这里用“V1 定方向、V2 验链路、V3 上规模、V4 按失效扩量”串起设计过程。前两阶段的名称概括各自的设计重点，实际运行参数及数据规模按档案记录。

| 阶段 | 设计时要回答的问题 | 实际推进与证据 |
| --- | --- | --- |
| V1 · 方向设计 | 每个任务的输出是什么，画面中有什么可见证据，先需要哪种数据与标签？ | 早期逐任务方案确定检测、状态、计数或 Pose 等路线，再用覆盖类别的 50 张训练图快速试跑。V1 记录为 320 像素、SGD、学习率 0.01、1 轮。 |
| V2 · 小规模验证 | 同一批数据能否稳定走完图签读取、训练、验证、测试和归档？扩大训练预算前还缺什么？ | 沿用同一批每任务 50 张训练图、固定集合和引擎契约，学习率改为 0.005，训练 2 轮。V1/V2 合计九项、18 次训练及 Val/Test 评估。 |
| V3 · 批量扩展 | 能否把各任务的素材和生成方式转成千图级数据，在不同训练机完成训练并回传？ | 八条完整运行的输入清单合计 30,725 张训练图、1,972 张验证图、4,180 张测试候选。人物生产训练中止。内域验证和冻结实拍诊断分别记录。 |
| V4 · 需求收敛与规模化生产 | 新增图片覆盖了哪些真实失败，图签能否按任务、父来源和用途正确进入生产与评估？ | 范围收敛到八项，车牌沿用省赛模型。任务分别配额、试制、验证、批量导出和微调。11 月 19 日阶段报告记录人物 3,000／300／300、仪表 6,480／1,080／1,080（Train／Val／Test），电动车仍为 108／10 的有界基线。 |

以上规模采用各阶段原记录，V3 的测试候选数量与 V4 的实际导出是不同口径。V1/V2 使用相同训练子集，两轮在预算和学习率上同时变化，指标可描述当时配置的结果。相邻 VisualRecognition 仓库的任务内编号按自身记录解释。[早期任务方向](../research/OPEN_SOURCE_METHODS.md) · [V1、V2 与 V3 运行记录](../TRAINING_WORKFLOW.md#v1v2-与-v3) · [V3 规模和覆盖分析](../research/DATASET_COVERAGE_TRAINING.md) · [V4 阶段报告](../research/DATASET_MODEL_REPORT_20261119.md)

## 从试跑到规模跃迁

**V1 先拆任务。** 人物需要分清目标立牌与白背干扰，垃圾桶要分别识别盖态与桶面图案，仪表最终要给出两项读值。早期设计先把这些业务结果拆成检测框、类别、关键点及后续规则，并盘点实拍、旧素材和可做的合成。小训练子集让错误尽早暴露在配置、图签、类别和输出链路上。

**V2 在有限规模上补全过程。** 沿用覆盖类别的同一子集和固定验证、测试入口，跑完指标、图表和运行归档。垃圾贴纸训练子集保留 24 类。低预算下的弱指标说明完整跑通和模型可用是两项验收。同一小集合也给批量训练前的环境、文件路径和产物交接提供了复查样本。[训练记录](../TRAINING_WORKFLOW.md#v1v2-与-v3) · [技术版本索引](../../Archive/technical/revisions/README.md)

**V3 扩大生产与分发。** 生成器和增强把任务推到数千图级，任务训练配置、独立运行目录与便携依赖承接跨机工作。训练回传后，固定实拍诊断揭示了原来的覆盖缺口。仪表对 4 张原合成验证图都有表框，在该轮 548 张现场输入上没有超过 0.01 的预测。火焰误识别灯具，低机位电动车和截断车辆漏检，垃圾桶发生盖态错分。增量必须解释它覆盖的视角、材质、遮挡或干扰物。仅增加同一母样的亮度变体，会增加训练和复核成本，对这些失效的覆盖仍有限。[V3 同场地诊断](../research/FIELD_EVALUATION_V3_20261112.md#实拍失效)

## V4 如何把需求变成可生产的数据

1. **明确监督对象和业务边界。** 把比赛需求、学习目标和图像干扰条件分别写入现有配置。比如火焰框、所属楼体和逐楼计数可以分别核对。楼面未观察完整时保留未知，减少把不可见目标当零例的错误。整帧空负、局部硬负和待复核各有用途。[识别需求](../../config/perception_tasks.json) · [学习目标](../../config/task_targets.yaml) · [组合轴](../../config/combination_axes.yaml)
2. **先在小样核成本与可行性。** 用直接实拍刻画真实材质、光影和相机条件，用 Blender 控制机位、几何、遮挡和阴影，用 Python 在真实或渲染底板上批量编排可行组合。先核框、关键点、背景是否保留原目标标签，以及前景的贴面、接地和遮挡。历史火焰候选的 607 张图已经生成，但有贴放支撑未核清、覆盖窗户等问题，归档供复盘。这个案例说明小样阶段的几何核对能减少整批返工。[技术归档](../../Archive/technical/README.md) · [数据制作流程](../DATASET_PRODUCTION.md#从原始采集到导出)
3. **按有用变化扩量。** 组合轴围绕已观察的失败编排。同一桶色切换开闭、同一状态换桶色，减少状态与颜色的固定绑定。火焰、楼名可共享楼面来源，各自核对框与载体关系。以分集的缺口、来源容量和算力确定配额，记录计划、实际成图数和实例数。保留相邻帧用于时序与同路线诊断，独立评估按父视频、实物布置或母场景划分。[数据源配对](../DATASET_SOURCE_PAIRING.md) · [全量计划设计](../FULL_TRAIN_PLAN_DESIGN.md)
4. **用结果决定下一轮补什么。** 正式基线回传后，先看整图错在哪一类，再补反光、斜视、负背景或局部遮挡。V4 火焰精简训练数据后做 10 轮微调，固定 Test 的 TP 从 475 到 480、FP 从 9 到 4。桶开闭的真实桶主导候选则使历史 Test 整图全对从 225/253 降到 193/253，该候选保留为对照。这两项都要按测试来源和分母解释，也说明追加实拍或扩量之后仍需复测。[V4 模型效果与微调](../research/DATASET_MODEL_REPORT_20261119.md#任务效果与微调结论)

## 多任务如何并行并整理清楚

| 要管理的对象 | 工作方法 | 这样可以回答的问题 |
| --- | --- | --- |
| 共用原片和 Blender 工程 | 媒体可共用，逐图按任务记录语义及用途。统一工程由一个写者保存，独立渲染进程读取项目并各写自己的批次目录。 | 哪些任务共用了同一底图、物料或机位？某个批次能否按生成时工程复查？ |
| 需求、计划和生成 | 共用能力放在共享脚本，各任务维护独立配方和输出。全局登记引用任务入口，批次回执保留实际消费的输入。跨窗口只协调明确的文件和责任，共享库、清单与 Git 索引串行写入。 | 改的是某一任务配方、共享契约，还是生成过的某个批次？ |
| 大量图签与分集 | 区分原件、标注候选、试制小样、正式分集和训练包。用逐图记录、父来源、清单和实际图签对账，核对图片与标签配对和跨集复用。 | 哪些图片真正进入训练？多少是来自同一视频或资产的变体？ |
| 历史和当前入口 | 当前入口指向实际使用的配方与产物。被替代的输入、运行记录和来源快照按历史归档保存。可重建媒体索引用于查图，生产回执负责复查当时实际生成了什么。 | 哪一套是当前使用的？旧结果使用的是什么输入？归档中还能恢复哪些内容？ |

V4 的整理结果是共享场景与生产能力可复用，任务的标签、配额、分集、训练和结论可单独核查。数据规模同时看成图数、实例数、独立父来源和关键组合覆盖。这样可以定位扩量补到了哪类实物证据，也能判断什么时候把预算转回实拍、标注复核或固定机位优化。[协作与共享写入](../../datasets/DATASET_COORDINATION.md#窗口通信与共享写入) · [数据区与 Blender 接线](../../datasets/README.md#单文件编辑与生产接线) · [技术归档及范围](../../Archive/technical/README.md)
