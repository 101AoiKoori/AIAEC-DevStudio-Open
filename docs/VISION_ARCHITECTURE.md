# 视觉模型研发架构

本架构承载从任务目标到可交付 `.pt` 的视觉研发。实车运行、导航和比赛任务流程由协作方负责；视觉侧向对方交付所需模型文件。车牌沿用现有省赛模型，V4 数据制作针对八项任务。

## 从目标到模型

识别范围维护在 [perception_tasks.json](../config/perception_tasks.json)，监督目标维护在 [task_targets.yaml](../config/task_targets.yaml)，打破错误关联的对照维护在 [combination_axes.yaml](../config/combination_axes.yaml)。历史对照中包含助手归纳的内容，出处不明的条目按现有设计判断，逐项确认以用户指示为据。条件概率、贝叶斯和高斯是可比较的分配方法，能否改善覆盖和识别以实际数据和运行结果判断。

[视觉研发 Skill](../.agents/skills/vision-model-workflow/SKILL.md)负责从当前证据接续任务、组织数据和训练、核对交付；[数据制作 Skill](../.agents/skills/dataset-production-loop/SKILL.md)负责实际推进任务批次。识别规则、数据契约和任务配置由各自的维护入口提供。

## 数据制作的全局与局部

| 范围 | 负责的决定 | 维护位置 |
| --- | --- | --- |
| 全局契约 | 图像、实例和父来源如何识别；图签怎样配对和交给训练；如何记录任务用途、split、实际产出和复用；如何安全发布生成结果。改变这些含义会影响跨任务共用记录或训练消费者。 | [编号与记录](ID_AND_COUNT_POLICY.md)、[媒体记录](DATASET_DESIGN.md#媒体记录与查询设计)、[共享执行入口](../datasets/scripts/README.md#公共能力和输出) |
| 任务设计 | 要识别什么、什么可标、哪些负例和组合能检验错误依赖、需要哪些空间或表面证据。人物决定可辨正面和白背对照，温湿度表决定八点可见性和反光对照。 | 学习目标和组合轴各自的 `tasks.<任务>` 条目，以及[对应任务入口](../datasets/scripts/README.md) |
| 任务批次 | 此次实际选哪些源、分给哪个 split、如何安排可行布局、采用哪种分配方法、预算内生成多少。记录缺项和实际产量，已有批次从其计划及回执追溯。 | `datasets/scripts/<任务>/config/`、本任务生成入口、该批次清单与回执 |

判断归属时看决定作用于谁。一张底图的身份、父来源和坐标约定由共享记录提供；能否作人物空负、仪表底图或贴纸底图，由接收任务按本用途证据决定；哪一批用了它，由该批次记录。集中 YAML 里的任务条目仍归各任务，`common/` 也可以提供可选工具。共享分配器接收任务已设计的状态和预算，组合、权重和实际选源由任务决定。

组合轴文件记录设计，[组合轴观察](../config/combination_axis_observations.yaml)保留迁移前的历史快照。电动车和禁行牌的计划可保留设计版本与交叉 ID，实际覆盖须由生成清单与图签核对。
